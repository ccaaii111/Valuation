# A 股估值系统

输入一个 6 位股票代码，这个项目自己联网取数、自己把每一个估值假设算出来、自己给出每股价值，并把每一步的出处留在磁盘上。你不必填任何原始财务数据。你能改的只有假设，改完之后它会告诉你这一处改动值多少钱。

现在实现的估值方法是绝对估值法（现金流折现）：FCFF 与 FCFE 两种口径，各配 Gordon、退出倍数、UEM 三种终值，一次给出六个每股价值。

---

## 1. 它能做什么

| 能力 | 具体是什么 |
| --- | --- |
| 取数 | 一趟联网调十个来源：东方财富 F10 的三张报表与主要指标、一致预期、行情快照、个股周频收盘价、七个市场基准指数的收盘序列、10 年期国债收益率、指数收益、分红送配明细、全市场股票名录。全部免登录，代码里没有任何账号、令牌或密钥。 |
| 算假设 | 把原始数据折算成 54 行假设，分七组：收入预测、盈利与税率、再投资与营运资本、资本结构与桥、折现率、终值与口径、市场与股本。每一行都带着它是怎么算出来的、以及证据存在哪个文件里。 |
| 定价 | 六个每股价值、逐年现金流明细、两种口径之间的自洽性校验、终值占现值的比例。 |
| 留凭证 | 这一次用到的每个原始响应都存进 `runs/<代码>/<批次>/raw/`。拿同一份凭证以后随时可以不联网重算（`--from-run`），算出来的每个数与当时相同。 |
| 改假设 | 在网页面板或推导图上改任意一行可编辑的假设，实时看每股价值怎么动、这一行单独值多少钱。改动单独存 `manual.json`，机器自己算的那份基线永远原样留着，随时能比。 |
| 找股票 | 搜索页支持代码、名称、全拼、简拼。 |

它不做的事情同样明确：不做行情推送、不做组合管理、不做多因子回测、不接需要登录的数据源、不给买卖建议。

## 2. 它怎样估值

五个步骤，顺序固定，前一步的产物是后一步的输入。下面的数字取自 2026-10-25 对 600519 贵州茅台的一次真实建链（报表截至 2026-06-30，批次 `20261025-193719`）。你在自己机器上重跑同一只票走的是同一套算法，只是行情与报表会往前移。

| 步骤 | 做什么 | 这批的结果 |
| --- | --- | --- |
| 1 取数 | 十个来源取回，原始响应落盘 | 10 个来源、约 5 MB 凭证 |
| 2 期间口径 | 东财给的是 Q1／H1／Q9 的累计值，先换算成年度序列和滚动十二个月 | 营业总收入 LTM 1,732.38 亿元 |
| 3 正常化 | 定价用的营业利润先剔掉非经常性损益：营业利润 + 利息费用 − 公允价值变动收益，再按当年税负把偶发额折算进分子 | 显性期首年 EBIT 率 66.12% |
| 4 假设链 | 54 行假设逐行推出来：收入路径 → 盈利与税率 → 再投资 → 折现率 → 终值 | 无风险利率 2.29%、β 0.2169、股权风险溢价 7.45% → 股权成本 3.90% → WACC 3.90%；永续增速 0.00% |
| 5 定价 | 两种口径 × 三种终值，六个结果各带明细 | 每股 2,010.13 ~ 2,441.14 元 |

第 5 步的六个数：

| 每股价值（元） | Gordon | 退出倍数 | UEM |
| --- | --- | --- | --- |
| FCFF（企业口径） | 2,441.14 | 2,010.13 | 2,436.87 |
| FCFE（股权口径） | 2,406.39 | 2,058.05 | 2,402.58 |

同一批还给出：终值占现值 71.6%、现价 1,335.00 元、两种口径的每股差 33.94 元（这笔差额是债务与现金之间的桥接项，不是两法分歧）、自洽性校验通过。

**预测是怎么长出来的**：前三年锚在券商一致预期上，其后逐年向永续增速回落，回落到几年由「显性预测期」那一行决定（默认 10 年，可以改成 12 年以内的任何值）。每年回落几个百分点是算出来的结果，不是你填的输入。其他报表项按「比率不变 × 营收」外推，比如 EBIT 率、折旧摊销占营收比、营运资本占营收比。

**测不准的东西它不编数**：无风险利率取不到就把那一行留空并提示；债务成本算出越界就退回惯例值，并把被拒绝的算法写在证据里；β 回归出零或负数就报「CAPM 不适用」，整条链不出估值，而不是替你换成 1.00。

## 3. 假设链表：54 行长什么样

| 组 | 行数 | 这一组决定什么 |
| --- | --- | --- |
| 收入预测 | 8 | 未来几年的营收、增速路径、增速的锚点从哪来 |
| 盈利与税率 | 9 | EBIT 率、正常化剔掉的偶发额、实际税率 |
| 再投资与营运资本 | 5 | 折旧摊销、资本开支、营运资本变动——折现折的正是这几项 |
| 资本结构与桥 | 7 | 有息负债（含租赁负债）、现金、净债务，以及企业价值到股权价值的桥 |
| 折现率 | 12 | 无风险利率、β、股权风险溢价、股权成本、债务成本、WACC |
| 终值与口径 | 10 | 永续增速、显性预测期、退出倍数、UEM 的再投资率 |
| 市场与股本 | 3 | 现价、总股本、总市值 |
| **合计** | **54** | |

按「定价认不认这一行」分三种身份：

| 身份 | 行数 | 面板行为 |
| --- | --- | --- |
| 进定价 | 32 | 有输入框，改动会被定价 |
| 由上游算出 | 2 | 锁死。只有股权成本和 WACC 两行，改上游即重算 |
| 只作对照 | 20 | 不给输入框。它们要么已经通过相邻行反映进结果，要么是纯对照 |

对照行是这个项目的一个习惯：**一件事进定价的只有一行，旁边并列几行是同一算法的其他窗口**。无风险利率有即期值与近 5 年中枢，股权风险溢价有今年以来／近 3 年／近 5 年／近 10 年四个窗口，永续增速有保守／中枢／乐观／再投资四档。摆在一起是让人判断级联采用的那一档偏在哪一侧，而不是让它自己说自己是中枢。

改假设的填法：金额行（亿元、亿股）填「相比机器基线 ±%」，比率与参数行直接填数值（填 2.5 就是 2.5%）。基线为 0 或负数时百分比没有意义，那一行自动退回绝对值框。

## 4. 推导图：`/derivation`

面板上的 54 行是一张大表，推导图把同一批数据画成上下游关系：

- 层号由上游链的最长深度算出来，边只连真有出处关系的两行。上面那批是 4 列：最左列 33 行是原始取数与惯例值，往右是比率与收入路径，再往右是股权成本与首年 EBIT 率，最右列是 WACC 这类折现率结果。
- 实线表示这一行是当场重算的，改了上游它立刻动；虚线表示它的上游只在建链那一刻算过一次，要改得重跑取数。那批 53 条边里 7 条是虚线。
- 点一行会放大：浮层里只画这一行加上游两跳，并把这一行的算式写出来。Esc、返回按钮、点暗处，三条退路。
- 图上改数就是面板改数：同一个后端接口、同一份 `manual.json`、同一套重算。
- 图里不含任何估值结果字段（有测试钉住这条），它只回答「这个数是怎么来的」。

行列数随批次而变：某一行缺证据就不落进图，各只票的报表项多少也不同，所以别把上面这组数当常量。

## 5. 怎么用

```bash
# 建一条假设链（联网，约 20~60 秒；名录里没有这只票时一个请求都不发，退出码 3）
python scripts/build_baseline.py 600519

# 出估值：六格矩阵 + 明细 + 自洽性校验
python scripts/run_valuation.py 600519

# 面板
start_panel.bat                     # 或 python scripts/serve_panel.py
#   http://127.0.0.1:8765/            首页
#   http://127.0.0.1:8765/search      搜索（代码／名称／简拼）
#   http://127.0.0.1:8765/panel       假设链面板
#   http://127.0.0.1:8765/derivation  推导图
```

面板上只需要一个按钮：在首页或面板顶部输入代码，按「取数估值」，系统自己判断该不该联网——盘上这批还在有效期内就不联网、直接复现给你看；过期或凭证缺了就联网重取。同一趟取数会把七个市场基准的收盘序列一次备齐，之后换基准只是离线复现（约 0.1~0.5 秒，另起一个新批次，老批次不动）。取数在后台线程跑，页面轮询步骤名，跑完自动读回来。

常用的命令行变体：

```bash
python scripts/build_baseline.py 600519 --from-run 20261025-193719  # 用旧批次的原始答复重算，另起一个新批次
python scripts/build_baseline.py 600519 --benchmark 000300         # β 改对沪深300 回归（这批没预取过它就先在 β 那条腿失败）
python scripts/build_baseline.py 600519 --horizon 12               # 显性预测期从默认 10 年拉到 12 年
python scripts/build_baseline.py 600519 --beta 0.90                # β 算术不成立时的人工值
python scripts/build_baseline.py 600519 --risk-free-basis spot     # 用即期 10Y 而不是近 5 年中枢定价
python scripts/build_baseline.py 600519 --terminal-growth-basis central
python scripts/build_baseline.py 600028 --exclude-lease-debt       # 租赁负债不计为债务
python scripts/build_baseline.py 600519 --no-normalize             # EBIT 率分子退回报表原值，不剔非经常性损益

python scripts/run_valuation.py 600519 --attribution               # 每一行改动单独值多少钱
python scripts/run_valuation.py 600028 --method fcfe --terminal uem --rate 0.09
python scripts/run_valuation.py 000858 --overrides runs/000858/<批次>/manual.json   # 用面板存过的那份修正
```

## 6. 怎么部署

**仓库里有什么**：克隆下来是四个文件加四个目录，`data/` 和 `runs/` 要等程序第一次跑起来才出现。

```
backend/                程序本体，命令行和网页用的是同一套代码
  builder.py            建一条假设链的完整流程：查名录 → 十路取数 → 算出 54 行假设 → 写盘
  data/                 联网取数，一个文件管一类外部数据；原始响应的落盘与读回也在这儿
  model/                离线计算：期间口径、正常化、54 行假设、β 回归、折现引擎、单行归因、推导图数据
  web/                  网页服务：4 个页面、9 个 JSON 接口、后台取数线程、runs/ 的读写
scripts/                六个入口：build_baseline 建链、run_valuation 出估值、serve_panel 开面板、
                        update_universe 重拉名录，另有两个针对偶发崩溃的复现脚本，平时用不到
tests/                  29 个测试套件（全部离线）、fixtures.py 的假公司数据、run_all.py 一次跑完、
                        dom_derivation_check.js 检查页面脚本
docs/caliber.md         每一个数凭什么、公式推导、常数表、已知限制
data/universe.json      股票名录缓存，7 天内复用；不在版本库里
runs/                   每次取数留下的原始响应与算出来的基线，按代码和批次分目录；不在版本库里
requirements.txt        五个依赖包及版本
start_panel.bat         Windows 下双击开面板
.gitignore              排除 runs/、data/universe.json、缓存和日志
```

模块级的职责分工（哪个文件负责哪一步）写在 `docs/caliber.md` §3。

**环境**：Python 3.13（实测 3.13.5，anaconda base）。直接依赖五个包，版本钉死，见 `requirements.txt` 顶注：`pandas` 3.x 与 `akshare` 的取数返回结构有耦合，升级任何一个是先跑一遍测试再动代码。

```bash
python -m pip install -r requirements.txt
```

**网络要求**：这台机器要能直连东方财富（F10 与行情端点）、中证指数官网、新浪、乐咕的公开数据接口。没有代理配置项，走系统默认路由；程序不发送任何身份信息，也不接收任何凭据。

**股票名录**：面板启动时先看 `data/universe.json`，没有或已旧过 7 天就重拉一次全市场名录（当前 5,577 只，约 600 KB），拉不到就退回旧索引并打印它旧了几天。名录是准入判断的唯一依据：名录里没有的代码，一个取数请求都不会发出去（CLI 退出码 3，面板新鲜度那一行写「查无此票」）。刚上市的票被误拦时重拉：`python scripts/update_universe.py --force`，或 `serve_panel.py --refresh-universe`（约 30~60 秒）。除此之外没有绕过名录的开关，这是决定，不是遗漏。

**面板怎么常驻**：`serve_panel.py` 默认只监听 `127.0.0.1:8765`（`--host`／`--port` 可改）。它是单用户本地工具——没有登录、没有鉴权、没有并发写保护（两个人同时改同一只票的 `manual.json`，后写的覆盖先写的）。要让别人从别处访问，请自己加反向代理和认证，程序本身不提供。

**产物放在哪、占多少**：每一次建链在 `runs/<代码>/<批次>/` 下写约 5 MB——`raw/`（原始答复）、`manifest.json`（每个来源的取数时间与指纹）、`baseline.json`（54 行假设）、`manual.json`（你改过的行，只有改过才有）。这些和 `data/universe.json` 都是本地产物，已写进 `.gitignore`，不在版本库里：克隆下来盘上没有批次，删掉批次也不影响代码，随时可以重取。

**退出码**：

| 码 | 含义 | 出路 |
| --- | --- | --- |
| 0 | 正常 | |
| 2 | 行情取不到，或者 β 在这只票身上算术上不成立（没有行情快照、重叠不足三周、回归出零或负数）。整条链不出估值，`raw/` 与 `build_failed.json` 照落盘 | 人工给值：`--beta 0.9`；或面板表头那个「贝塔」框 |
| 3 | 名录里没有这只票（退市、代码写错、或刚上市还没进索引）。一个来源都不碰、一个批次目录都不开 | 核对代码；确是新票就重拉名录 |

**测试**：

```bash
python tests/run_all.py
```

29 个套件，不用第三方框架，全部离线：数据用替身，批次写进临时目录，不碰网络也不碰 `runs/`。另有 `node tests/dom_derivation_check.js`（71 项检查）把页面脚本原样读进沙箱、打本机面板的真接口，钉的是页面渲染与交互那一层——它要面板在跑且 `runs/<代码>/` 里至少有一批，缺任一样就报「跳过」，不算失败。
