# 口径与实测记录

这份文件回答「每一个数凭什么」：十个来源的端点与失败形状、期间口径、55 行假设链的逐行读法、公式推导、常数阈值、已知限制。
项目能做什么、怎么用、怎么部署在 [`../README.md`](../README.md)。章节号是 §2–§12，代码与测试注释里那些「docs/caliber.md §12 第 16 条」的引用指的就是这里的编号。

下面大量出现的 `runs/<代码>/<批次>` 是某一次真实取数落下的凭证。它们是本地产物，不在版本库里（`.gitignore` 排除了 `runs/`），所以克隆这份代码时盘上一个都没有；多数句子写明了它是联网取的那一批还是离线复现的那一批，照同一条命令重跑就能自己复算出同一套算法——行情与报表会往前移，绝对数值会变，不变的是判据。

## 2. 设计立场

| 立场 | 落地方式 |
| --- | --- |
| **只用免登录免费数据源** | 东财公开接口（三表、一致预期、行情）+ akshare（国债收益率、周频行情、股票名录）。无账号、无 token、无密钥，代码里不存在任何凭据。 |
| **估值输入不留本地缓存** | 每一次估值用到的每个数，都必须在 `runs/<代码>/<批次>/raw/` 里有一份当次联网的原始响应作凭证。本地只有两类文件：凭证（raw）与从凭证算出来的结果。 |
| **机器基线 + 人工修正双轨** | 机器先把假设链填满（`baseline.json`，只读），人的改动单独存 `manual.json`。两者永不互相覆盖，所以「机器认为值多少」始终可复原。 |
| **可推导优先于简洁** | 行与行之间的出处关系写死在 `assumptions.DERIVES` 里，`/derivation` 页面据此画图：第 0 列是原始取数与惯例值，越往右离取数越远，最右边是引擎步骤。 |
| **测不准就说不准，不编数** | 无风险利率取不到就留空并提示，不会凭空给一个 3%；债务成本实测越出护栏就退回惯例值、并把被拒的算法写进 note；β 回归出非正数就报 `BetaNotApplicable` 拒绝出估值，而不是替换成 1.00。 |
| **单一计算路径** | 面板、推导图、CLI 共用 `backend/builder.py` 与 `backend/model/dcf.py`。画图代码不许再跑一遍引擎——`tests/test_derivation_graph.py` 会哨兵式检查图载荷里不含 `per_share`/`equity_value` 等估值结果。 |

不做的东西同样明确：不做行情推送、不做组合管理、不做多因子回测、不接任何需要登录或密钥的数据源。

## 3. 目录结构

一个文件一行，说它负责什么。命令行和网页面板用的是同一套 `backend/`，不存在两份实现。

```
backend/builder.py        建链的唯一入口：先问名录这只票在不在市，再十路取数，然后算出 55 行假设，最后写盘。
                          CLI 与面板都调这一个文件，同一个代码两边产物一致。
backend/data/             联网取数，一个文件管一类外部数据
  em_company.py           东方财富的公开端点：三张报表、主要财务指标、一致预期、行情快照
  transport.py            发请求、把原始响应写进 runs/<代码>/<批次>/raw/、给每份响应算 sha256；
                          --from-run 复制旧批次也是这个文件做的
  fundamentals.py         把上面那些原始响应拼成一个财报快照，顺带把行情文本解析成字段
  macro.py                10 年期国债收益率：即期值与近 5 年中枢并列，单位跳变时判为不可用
  prices.py               β 用的行情：个股前复权周频收盘，加七个基准指数的约 11 年日频收盘，一趟并发取齐；
                          新浪与中证官网两条通道按代码挑
  market.py               ERP 用的市场收益：从同一份指数序列里切出基准指数收盘，有全收益指数的用它，
                          没有的退回乐咕的沪深两市股息率
  dividends.py            分红送配明细，只用来算再投资增速那一档对照值；十个来源里唯一一个取不到也不报错的
  marketcache.py          市场级数据的本机缓存（国债序列、指数收盘账本、全市场股息率）：当天同一根收盘轴内复用，
                          只省联网，不省证据——每批 raw/ 与 manifest 照旧写全（§4.8）
  freshness.py            判断盘上这批还在不在有效期，也就是按下「取数估值」到底要不要联网
  universe.py             全市场 code→name 索引：搜索页用它，取数前用它判断这只票还在不在市；
                          它不提供任何进模型的数
backend/model/            离线计算，不碰网络
  periods.py              期间口径：Q1／H1／Q9 的累计值换算成年度序列、滚动十二个月、上年同期
  normalize.py            把官方披露的扣非差额搬到 EBIT 那一层：定位置、折成税前额、六道护栏
  assumptions.py          55 行假设的定义：每行的算法、常数、取数规则，以及行与行的出处关系（DERIVES）
  beta.py                 周收益对基准指数的最小二乘回归，纯函数，输入是两份收盘价字典
  dcf.py                  折现引擎：FCFF 与 FCFE、三种终值、六格矩阵、自洽性校验、两种口径之间的桥
  recompute.py            改一行之后哪些下游要跟着重算，按上游到下游的顺序算；人工改过的行当常量
  attribution.py          单行归因：这一行相对机器基线改了多少、单独值多少钱
  derivation.py           推导图的数据：层号、边、每行一句显示用公式；只换画法，不重算任何数
backend/web/              网页层
  api.py                  组装页面要的那份 JSON；只有请求新基线时才去取数
  app.py                  Flask：4 个页面、9 个 JSON 接口、1 个静态资源路由
  jobs.py                 后台取数线程，页面轮询步骤名；同一只票同时只跑一个作业
  store.py                runs/ 的目录布局，只有这个文件知道批次目录长什么样
  static/                 四个页面 home／search／panel／derivation，加共用的 common.js 与 app.css
data/universe.json        股票名录缓存，7 天内复用；盘上没有时程序自己拉一份
data/market_cache/        市场级缓存那三段（§4.8），一次市场公共数据一份 JSON；删了只是回到从前每批重取
runs/<代码>/<批次>/       一次取数的全部产物：raw/ 原始响应、manifest.json 每个来源的取数时刻与指纹、
                          baseline.json 55 行基线、manual.json 人工改动、失败时的 build_failed.json
scripts/                  六个入口：build_baseline 建链、run_valuation 出估值、serve_panel 开面板、
                          update_universe 重拉名录，另有两个只服务于 §12 第 16 条那次偶发崩溃的
                          repro_prefetch_abort 与 probe_prefetch_warmup
tests/                    30 个 test_*.py 套件、fixtures.py 的假公司数据、run_all.py 一次跑完、
                          dom_derivation_check.js 检查页面脚本（判据见 §10 末）
docs/caliber.md           本文件
requirements.txt          五个直接依赖包及版本
deploy_panel.bat          Windows 下双击：建 .venv、按 requirements.txt 装包、开面板
start_panel.bat           Windows 下双击开面板，依赖得已经装好
.gitignore                排除 runs/、data/universe.json、data/market_cache/、.venv/、缓存与日志
```

`data/` 与 `runs/` 都不在版本库里：克隆下来这两个目录并不存在，第一次取数才会把它们建出来。`deploy_panel.bat` 建的
`.venv/` 同理。批次落盘的具体格式、分源新鲜度阈值和模块之间怎么串，见 §4 与 §5。

## 4. 一个数从哪里来：取数 → 期间口径 → 假设链 → 引擎

### 4.1 十个来源，固定顺序

第 9 源最多打三个端点，但只算一个来源：`manifest` 里它是一条 `market_returns`，凭证把三条腿的原始答复一起存进 `raw/market_returns.json`。中证官网那个接口必须显式给 `start_date`/`end_date`，否则序列会凭空停在 2024-06-04；它还会把请求的起始日原样回显成首行（值与下一个真实交易日相同），解析时按「首行与次日同值」丢掉，不然样本计数与跨度护栏都被一条不存在的读数带偏。

第 10 源也走 akshare，但**不走 `em_company` 那条东财 REST 通道**：`stock_fhps_detail_em` 是 akshare 的函数，和 `prices.fetch_frame` 共用同一套重试与 stderr 收敛（akshare 在这里会起 tqdm 进度条）。它排在 `fundamentals.fetch` 的末尾——东财七路取完之后。加它之前先回答了一个问题：**它参不参与定价？** 答案是不参与（默认档只用它出对照行），所以它既不进 `freshness.evaluate` 的 `expected` 清单，也不许在失败时抛错——一个只作对照的来源要是能把所有老批次一夜判旧，代价与收益完全倒挂。缺凭证的答复是「这一档不可用」，不是「这批作废」。

前四个用 `columns=ALL&pageSize=200&sortColumns=REPORT_DATE`，所以拿到的是**累计值**（Q1/H1/Q9）与**全年值**（FY）混排的多期数据——这就是 §4.3 那层期间口径存在的原因。

`main_indicators` 落盘为凭证，模型只从里面读一个字段：`ROEJQ`（东财官方的加权净资产收益率）。再投资增速要用 ROE，而重算 ROE 就得再造一套净资产口径（期初/期末、归母/全体、增发与回购的加权方式），那套口径和东财公布的数会长期对不上；用官方那一列，凭证与数字都在同一张表里可查。其余 164 列仍是留给人的交叉参照。

这十路取数之前还有一道**准入**（不占序号，2026-10-15 加）：`builder.admission()` 拿 `data/universe.json` 问一句「这只票还在不在市」，名录没有它就抛 `TickerUnavailable`（CLI 退出码 3，面板把「✗ 查无此票」写在新鲜度那一行且按下不排队），**一个来源都不碰、一个批次目录都不开**。名录在这儿只回答准入门，产出的不是任何一个进模型的数；它答不了的两条一律放行（盘上没有索引、索引旧过七天），复现路径根本不查它。为什么要有这道门、它买到了什么、仍然管不到什么，都写在 §12.12。

### 4.2 批次落盘：凭证、指纹、复现

```
runs/600519/20260924-134806/
  raw/income_statement.json    ← 原始答复本体
  manifest.json                ← 每个来源的 url、fetched_at(UTC)、sha256、相对路径
  baseline.json                ← 55 行机器基线（只读。行数随口径长过：盘上实测 2026-09-23～10-13 是 47 行，10-13～10-16 加了 ERP 三行成 50 行（10-16 有一批是 51 行的过渡形状：ERP 三年档换五年档、多了可持续增速那一行），10-20～10-21 加「显性预测期」成 52 行，10-22 加「非经常性损益剔除额」成 53 行，10-23 加「归母净利润 LTM」成 54 行（这一档的复现批没留在盘上，见 §12 第 20 条④），10-31 加「少数股东损益 LTM」成 55 行；更早的 09-21～09-22 还有 37/38/43/45 行）
  manual.json                  ← 人工修正（绝对值）+ 当时口径，由面板「保存修正」写
  build_failed.json            ← 建链失败时才有：{error, reason}
```

- 目录名精确到秒，同一秒撞车就等一秒，绝不互相覆盖。
- `--from-run` **不改源批次**：它把源批次的 `raw/` 复制成一个**新批次**（`RunStore.fork`），新批次的 `created_at` 跟着证据走而不是跟着目录走——这次建链没联网，凭证的取数时刻仍是源批次那一刻。`snapshot_ref` 记「当初真正联网的那一批」，连复现两层也不会指错。
- 因此同一份原始答复可以并存多个口径的基线（`--exclude-lease-debt`、`--risk-free-basis spot` 各起一批），源批次的 `baseline.json` 原样不动。
- **这一批用的市场基准记在 `manifest.json` 的 `benchmark`，不记在 raw 里**：raw 是多个基准共用的一份预取账本（§4.7），而 `--from-run` 复制 raw 原样带走，所以凭证说不出「这一批实际按谁算的」——只有每批各写一份的 manifest 说得出。老批次的 manifest 还没有这个键，读取处退回两份凭证各自的 `used_benchmark`／`benchmark.code`；三处都没有（`--beta` 建链没取行情）就读成空串，**没有证据就不声称知道它用过谁**。

### 4.3 期间口径：累计值 → 年度与 LTM

东财报表行带 `REPORT_DATE`，按月份尾判期间：`03-31→Q1`、`06-30→H1`、`09-30→Q9`、`12-31→FY`。

- **年度序列** `annual_rows`：只取 FY 行，按年份建字典（同年多行取第一条，已在 desc 排序后）。
- **LTM**（任何比率的分母都用它，因为最新披露往往是季报）：
  ```
  最新行是 FY        → LTM = 该行值
  最新行是 Qx        → LTM = 本年Qx累计 + 上年FY − 上年同Qx累计
  ```
- **上年同期** `same_quarter_last_year`：资产负债表取去年同一季末那一行，用于「平均有息负债」与「租赁净融资」。
- **CAGR** `cagr(series, 5)`：`(末年 ÷ 首年)^(1/跨度) − 1`，首年或末年非正则不给数。
- 任一金额为 `None`（科目缺失、停牌年）时相关比率直接缺该年，不做插补。

### 4.4 假设链 55 行：三种身份

`build_ladder()` 产出 7 组、共 55 行，每行带 `key / label / unit / source / kind / confidence / note / edit / derives`。按「引擎认不认」分三种身份：

| 身份 | 判据 | 面板行为 | 行数 |
| --- | --- | --- | --- |
| **进引擎** | key ∈ `dcf.ENGINE_INPUTS`（31 个） | 可编辑，改动会被定价 | 31 |
| **级联结果** | key ∈ `dcf.DERIVED_INPUTS` = `cost_of_equity`、`wacc` | 锁死，改上游即重算 | 2 |
| **参考行** | 其余 | 面板不给输入框；用 CLI/`manual.json` 填了会列进 `unpriced_edits` | 22 |

22 个参考行：`revenue_cagr_5y`、`anchor_source`、`consensus_dispersion`、`revenue_path`、`ebit_margin_hist`、`normalization_strip`、`ebit_margin_consensus`、`ebit_margin_start`、`da_to_revenue_hist`、`net_profit_ltm`、`cash_and_financial_assets`、`risk_free_spot`、`risk_free_norm`、`erp_ytd`、`erp_5y`、`erp_10y`、`terminal_growth_central`、`terminal_growth_optimistic`、`terminal_growth_sustainable`、`horizon_years`、`exit_pe`、`pe_ttm`。它们要么已经通过相邻行反映进结果，要么是纯对照（即期/中枢、今年/3 年/5 年/10 年、保守/中枢/乐观/再投资、股权口径倍数/企业口径倍数必须同时看得见，人才判断得出偏在哪一侧）。这是「一行进级联，N 行做对照」的第三次复用——前两次是 rf 的即期/中枢和永续增速的保守/中枢/乐观。

一句要当真的例外：`unpriced_edits` 那句「未被定价」是按身份说的（判据是 key ∈ `ENGINE_INPUTS`），不是按算术说的。有两行参考行恰好是运行时重导的**父项**——`cash_and_financial_assets`（`net_debt`、`roic_ltm` 的减项与分母）与 `net_profit_ltm`（`pe_ttm` 的分母）。面板不给它们输入框，所以这条告警一般只在 CLI `--overrides` 或面板载入一份别人写过的 `manual.json` 时才看得见；而在那条路上改它们确实会动价——`apply_overrides()` 末尾那趟重导会把新数带到进引擎的那一行上，同时仍把这一行登记成「未被定价」。要改这两行下游的数，正路是改下游那一行本身（`net_debt`、`roic_ltm` 都在 31 个键里；`pe_ttm` 自 2026-10-30 起退出定价，见 §12 第 23 条）。

那 31 个键里有两个不被 `evaluate()` 直接乘进算术，而是**经重导进定价**：`revenue_ltm`（只动三条 LTM 比率的分母，§12.4）与 `horizon_target`（它不进算术，只决定 `revenue_growth_path` 该有哪几年，§6.1）。面板照旧放行、归因照旧算得出，因为改动最终落在引擎确实读的那一行上——`apply_overrides()` 末尾那趟重导就是这两条路的岔口。

**编辑口径**：金额行（单位 `亿元`/`亿股`）的输入框是「相比机器基线 ±%」，比率与参数行直接填数值；基线为 0 或负时百分比没有意义，自动退回绝对值框。±% ↔ 绝对值的换算**只存在于浏览器**（`common.js` 的 `modeOf/toAbsolute/toBox`）——`manual.json`、归因列和 CLI `--overrides` 一律存绝对值，两处不可能分叉。

百分比行同理：人填 `2.5`，引擎存 `0.025`。

**顶层 `warnings`：不属于任何一行的告示**。`baseline.json` 除 `groups` 外还有一个 `warnings: []`，装的是「这批的折现率跟市场表现脱钩了」这类必须一眼看见、又没有一个行能安放的事实：ERP 实测越界或算不出来而退回惯例 `6.0%`、指数有全收益孪生却没取到而改走「价格 + 股息率」、定价有效税率越界而改走近五年均值或法定 25%、显性预测期被上下限压过（`--horizon 20` → 按 12 年走）、或那一年数在这只票身上意味着增速一年掉三个点以上／几乎不掉。纪律是**护栏不改数，但降级要出声**——同一件事在行内 note 里也写，note 是查到那一行才看得见的地方，`warnings` 是打开面板第一屏就该看见的地方。面板与推导图都把它渲染成顶部红条；老批次没有这个字段就读成空数组，不要求谁重跑取数。

### 4.5 面板只有一个「取数估值」按钮，新旧由这里判断

`freshness.py` 按来源分档（阈值不能一刀切，各来源的变动节奏差三个数量级）：

| 来源组 | 判定「该重取」的条件 |
| --- | --- |
| 报价 `quote` | 已发生的最新收盘日推进了（北京时间 15:00 之后算当天，之前退上一工作日） |
| 行情 `price_history` | 进入新的交易周（ISO 周号变大）；`--beta` 给定 β 时这项不参与判断 |
| 三表 | 下一个报告期的**法定披露截止日**已过：`3-31→4/30`、`6-30→8/31`、`9-30→10/31`、`12-31→次年 4/30` |
| 一致预期 / 无风险利率 / 市场收益率 `market_returns` | 距上次取数 > 30 天（后两者日频进位，但多年窗口的均值一个月才挪几个 bp，与 rf 同档） |
| 缺凭证 | manifest 里认不出上述任一时间戳 |
| 基准指数 | 面板/`--benchmark` 请求的指数**不在这批的预取集合里**（§4.7）。β 是相对指数的斜率、ERP 是相对指数的超额，换了市场组合的旧快照回答的是另一个问题，所以这条压得过有效期——但「另一个问题」只要那条序列已经在盘上就能答，于是集合内换基准不联网 |
| 分红方案 `dividends` | **不在表里，也不进 `evaluate` 的 `expected` 清单**（用户 2026-10-16 定的口径）。理由：这一档只出对照行，不进默认定价；把它列入 `expected`，那么 2026-10-16 之前建的所有批次都会因为「缺凭证」被判重取，一个参考来源把整仓库的证据作废，代价与收益倒挂。所以缺它的答复固定是「再投资档不可用：这批没有分红凭证」，那一行空白着，其余 54 行照旧 |

判断只读磁盘（manifest + baseline 的报告期 + 两份行情凭证的预取集合），绝不代替用户去取数；`force` 可以跳过它要一份新凭证。面板的市场基准下拉显示的是**这批快照实际用的基准**而不是本机默认值——显示错了会让人以为老批次是新口径；两份行情凭证都没有的批次不声称知道它用过谁，也就不据以强制重取。

换基准的答复有两个维度，按钮旁那一行把两者一起说清：这一跳缺不缺序列（请求的基准在不在这批的预取集合里，即 `benchmark.switch`），以及这批整体过没过期（`action`）。

| 情形 | 那一行说什么 | 之后发生什么 |
| --- | --- | --- |
| 请求的基准 ∈ 预取集合、≠ 这批用的，且这批还在有效期内 | `◇ 换成 沪深300 不联网（这批已预取它的序列）· 换过去就自动另开一个批次复现` | **换下拉就自动起一个复现作业**（`--from-run` 那条路）：读盘、按新基准重算 β 与 ERP、**写一个新批次**；源批次原样留着，一次网也不联（实测 0.1–0.5 秒） |
| 请求的基准 ∈ 预取集合、≠ 这批用的，但这批已有别的来源过了阈值 | `◇ 换成 沪深300 这一步不联网（序列已在盘上）· 但 20261025-193719 需重取：报价 · 6 天前取数，按下整批联网重取` | 不自动起作业。跳本身不缺序列，可这批整批要联网，复现出来的每股价值仍挂着昨天的收盘价 |
| 请求的基准在白名单或预取集合之外 | `● …需重取：基准指数` | 等按下，联网补指数那条腿 |

自动通路只走第一行：前端判据是 `action === "replay" && benchmark.switch`，两个值都读 `/api/valuation_status` 的答复，页面不自己再算一遍「这次联不联网」。作业在跑时也不自动起（那两个按钮正置灰），否则按下去只会撞上 `jobs` 里那句「已有一个作业在跑」，那一行照样先更新给用户看。要联网的那两档仍然等按钮——一次下拉滑动不该静默起一个几十秒的作业、写一份新凭证。

「另开批次」而不是原地改写，是为了守住 §4.2 那条纪律：任何一批的留痕都必须能单独复现它自己算出的数。原地改写完，前一个基准的 β 与 ERP 就没有对应的批次了。

这套判断与按钮机器（基准下拉、新鲜度那一行、起作业与轮询）住在 `common.js` 的「取数台」里，面板与推导图共用一份——两页各自只交回一个 `reload`（把跑完的新批次读进表格 / 重画成图）。`tests/test_routes.py` 钉住「只有一份」：页面里再出现一次 `function fetchValuation`/`showFreshness`/`refreshOptions`/`changeBenchmark` 就是分叉的开始。

### 4.6 哪条边当场算：图上的实线与虚线

推导图上每条边回答的是同一件事：**改了 `from` 那一行，`to` 这一格会不会跟着动**。答案不是全局的，是**这一批快照的**——所以判据落在 `recompute.live_rows(inputs)` 上，画法则只有两种：

| 画法 | 判据 | 含义 |
| --- | --- | --- |
| **实线** | 下游行 ∈ 该批次的 `live_rows` ∪ `dcf.DERIVED_INPUTS`（`cost_of_equity`、`wacc`） | 改上游即重算，一路传到每股价值 |
| **虚线** | 其余有上游的行 | 这个数只在建链那一刻算过一次，改上游不动它 |

虚线有两类来源，性质不同：

**一、永远虚线**：`risk_free`、`terminal_growth`、`anchor_source`。它们的「怎么算」要重新看原始凭证（rf 曲线、历年营收、一致预期覆盖到哪一年），行里那几个标量不够原料——硬说它会重算才是骗人。这三行的结果本身照旧进级联，改的是它下游那一格，不是它自己。`horizon_years` 从前也在这份名单里（年数是锚点覆盖广度的副产品，从行里读不出来）；显性期改成输入之后它变成了增速行的一个计数，原料就在行里，所以它是实线（§6.1）。

**二、M2 之前的批次虚线**：`revenue_cagr_5y`、`ebit_margin_ltm`、`da_to_revenue_ltm`、`capex_to_revenue_ltm`、`cost_of_debt_pretax`、`roic_ltm`。这六行的分子（LTM EBIT、折旧摊销、资本开支、利息费用、上年有息负债、净资产、CAGR 首末年）不在任何一行里，只存在原始报表，所以从前只能建链时算一次。`build_ladder()` 现在把这些标量抄进各行的 `raw`（金额与行同单位，亿元），带 `raw` 的批次这六条边就是实线：**改营收，LTM 比率跟着重算；改有息负债，债务成本跟着重算并过一遍护栏**（越界仍退回惯例 `3.1%`，跟建链时同一个口径）。缺 `raw` 的老批次照旧画虚线，一个数字都不会漂——想要这几条边活过来，重跑一次取数就行，不迁移存档。

原料是**逐行、逐字段**要求的（`NEEDS_RAW`）：只缺一个字段（比如有 `prior_debt` 没 `interest_ltm`）整行就算没料，退回虚线，而不是拿半个原料算出一个看着对的数；`revenue_cagr_5y` 更严——年报不足 6 年时建链那天就没算它，`raw` 里自然没有首末年，这一行也就一直是虚线。估值段那几步是引擎每次视图都重算的产物，不带 `live` 字段，缺省即实线。

还有第三种情形：**上游那一行根本不能改**。`normalization_strip` 就是——它的原料是逐年报表字段，不在链上任何一行里，所以它是第 0 列的一个根。它喂 `ebit_margin_ltm` 的那条边按下游判定是实线，但这条实线说的是「这个分子里含着那笔金额，改营收时重导出来的比率照旧用正常化后的分子」，不是「改剔除额会重算比率」；剔不剔是 `--no-normalize` 的事，面板上没有这个旋钮。它喂 `ebit_margin_hist` 的那条是虚线，因为均值行本来就不重算。

归属表由 `tests/test_recompute.py` 与 `tests/test_derivation_graph.py` 钉住：能当场算的边才许声明是活的，`live` 标记与边上的 `live` 必须一致，去掉 `raw` 的那六行必须变虚线且图形状不变。

### 4.7 一次取数把七个基准都备齐：预取账本

从前换一次市场基准必联网：一次数十秒、重打一遍免费源，而换的其实只是「相对哪个指数」——个股那三条腿、三表、一致预期、rf 一个字都没变。所以现在联网取数那一趟把下拉里所有基准都取回来，换基准于是退化成从同一份凭证里切另一条序列。

- **一个账本，两份凭证**。`prices.IndexSeriesMap` 是唯一的联网入口：`PREFETCH_CODES` = 七个宽基（`000905 000906 932000 000300 000001 399001 399006`）+ 四个全收益孪生 = 十一条指数序列，`raw/price_history.json` 与 `raw/market_returns.json` 存的都是这张表的两个投影（前者给 β，后者给 ERP），各自带 `used_benchmark`、`benchmarks`（预取到的那些）与 `unavailable`（没取到的那些及原因）。
- **并发，但进程里第一次初始化 JS 引擎要单独发生**。`WORKERS = 3` 的线程池同时拉多条序列，而 akshare 的 `stock_zh_index_daily` 每调一次就新造一个 `py_mini_racer.MiniRacer()`；两条线程同时去争进程里的「第一次初始化」会让整个当场炸在 `partition_address_space.cc`——连 traceback 都不留。所以账本开工前先单独建一个引擎上下文再丢掉（`prices._warm_v8()`），这件事由 `IndexSeriesMap.load()` 自己保证，不靠调用方记得。**坑的名字不是「主线程」**：实测落在后台线程上单独建一次同样安全（§12.16），面板那种「建链跑在作业线程里」的形态因此也被覆盖。`import akshare` 也留在开工前，但那只是为了不把慢 import 重复三遍——import 根本不构造上下文，挡不住这条坑。
- **一份长序列，多个窗口**。账本按 `LONG_HISTORY_DAYS`（约 11 年）下载；β 要的 1250 天窗口在本地按请求窗口切，不再回线上。`market.HISTORY_DAYS = prices.LONG_HISTORY_DAYS`，两处窗口写死成同一个数，免得「市场腿的十年」与「行情的十年」各走各的。
- **下游不认识新形状**。`prices.for_benchmark(payload, code)` / `market.for_benchmark(...)` 把多基准凭证切回建链从前见过的那一份（`stock` + 单个 `benchmark`），所以 `assumptions.py`、`beta.py`、ERP 那四行、引擎与面板全都没改一行。老批次的凭证本来就是单基准，切的时候原样交回；预取集合也据此读成「它那一家」。
- **失败隔离**：某个基准预取失败，它就整个不进集合——切到它照样判「需联网」，不会拿别的指数的数顶上去。缺的那一条是**指数**，所以报错文案点名「个股行情本身没问题，缺的是指数那一条腿」，而不是让人去核对 6 位股票代码。
- **代价**：每批 `raw/` 多约 1.2 MB（实测 `price_history.json` 190 KB、`market_returns.json` 985 KB，七条价格指数 + 四条全收益各约 2673 个交易日收盘）。留痕换切换，这笔磁盘是明写的。

`--from-run --benchmark X` 走的是同一条判断：X 在源批次的预取集合里就离线复现成一个新批次；不在，就先在 β 那一条腿响亮地失败（`基准缺序列`，退出码 2），因为 β 没有兜底值。只有同时给了 `--beta`（行情整条腿跳过）时链路才走到 ERP——那一行有 documented 的惯例值，于是它回退 `6.0%` 并出顶层警告，而不是炸链。两条腿的宽严不同是有意的，与 §4.1 第 8/9 源那两栏「失败时」写的正是同一套纪律。

### 4.8 市场级本机缓存：三段与「估哪只票」无关的数据，取一遍就存下来

`backend/data/marketcache.py`，落在 `data/market_cache/`。范围只三段，判据是同一条：这段数据换一只票会不会变。

| 缓存项 | 内容 | 从前每批的代价 |
| --- | --- | --- |
| `risk_free` | akshare `bond_zh_us_rate` 的 10Y 国债整段序列（§4.1 第 7 源） | 约 12 秒、234 KB；2026-10-29 相隔两分半取数的两只票，两份 `raw/risk_free.json` 逐字节相同 |
| `index_series` | §4.7 那本预取账本本体：11 条指数收盘（七个宽基 + 四个全收益孪生） | 约 28 秒，而且是 §12.16 那条会炸进程的坑唯一的入口 |
| `market_dividend` | 乐咕两市股息率（`stock_a_gxl_lg`，只喂 §5.5 无孪生那三家的降级腿） | 两条市场各一次 |

个股的三表、一致预期、报价、分红方案一概不进缓存——那些每只票不同，缓存它们就是把 A 票的数当成 B 票的。

- **「已经是最新」按收盘轴判，不按文件年龄**：`marketcache.fresh()` 比较缓存里那次真正取数与此刻各自落在哪一根已收盘日（`freshness.latest_close`，与 §4.5 那把尺子同一个函数）。同一根轴就算新——当天 15:00 之后重复点按钮免费，第二天上午（还没新收盘）也免费，跨到新收盘必重取；周末与长假不会让上周的序列冒充本周的，也不会凭空多要求一次联网。没有按「最后一个观测日」判是因为源发布有滞后：2026-10-29 15:08 取到的那份只到 10-28，若拿观测日当门槛，当天每一次都会判旧。
- **读侧四种情形一律按没缓存处理**，调用方照常联网：文件不在、JSON 读不出（半截）、`version` 不对、载荷是空的、判旧。与 `data/universe.json` 同一条纪律：缓存坏了不等于项目坏了，也不硬失败。
- **写侧只认「读到了数」**：负结果一概不落——rf 的即期读数被单位护栏拒掉（§5.5）时不落、账本里有任何一条腿失败时不落、股息率两侧都没读到数时 `save()` 因 `last_day` 为空而拒绝落盘。把一次源抖动钉成当天的默认答复，等于让这一天所有票都拿不到数。
- **证据纪律一处不动**：每批 `raw/` 里的文件照旧写全（内容就是缓存里那份原始答复，一个字节不减）；manifest 的 `fetched_at` 记缓存里那次**真正联网**的时刻，不记本次复制时刻——与 `RunStore.fork` 同一条口径（§4.2：取数时刻跟着证据走，不跟着目录走）。所以 §4.5 的新鲜度判断看到的仍是那一刻，「缓存把三天前的答复伪装成刚取的」在结构上发生不了。凭证里另外记一份 `reused`（哪条腿复用、复用哪一刻），面板与 CLI 那句留痕写「本机市场缓存复用，取数于 …」。
- **复现走不到这里**：`--from-run` 那一批已经有 `raw/`，「批次里已有快照就先读快照」那条分支在碰缓存之前返回。缓存只服务于联网建链。
- **命中时进程形态也变了**：`IndexSeriesMap` 从缓存端回数时不建线程池、不 import akshare、不预热 JS 引擎——§12.16 那条坑在命中路径上根本没有入口（这是顺带的好处，不是设计目标）。
- **两道开关**：CLI `--no-market-cache` 与面板的「强制重取」（`backend/web/api.py` 里 `force` 同时跳过新鲜度判断与缓存）。`force` 必须绕开缓存才配得上它名字里那个「重取」。

**单位约定**：金额一律 **亿元**（`round(元 ÷ 1e8, 4)` 存进基线），比率与增速是**小数**（面板显示成 ±x.xx%），倍数、价格、年数、布尔按字面。分年数据（`consensus_revenue`、`revenue_growth_path` 等）是 `{年份: 值}` 的 year-map。

### 5.1 收入预测

**`revenue_ltm` — 营业总收入 LTM · 亿元** · `data` · 进引擎
- 怎么取：§4.3 的 LTM 公式作用在 `TOTAL_OPERATE_INCOME` 上。
- 为什么锚 `TOTAL_OPERATE_INCOME`（营业总收入）而不是 `OPERATE_INCOME`（营业收入）：券商一致预期是按营业总收入建的，两个字段在茅台这类公司差异很小，但在有「其他业务收入」口径差的公司会让「预期 ÷ 历史」算出假增速。同源于最新披露，是缺一致预期时的回退基准。
- 作用：隐含 EV/EBITDA 的分母（也就是退出倍数两臂的参照）、以及 `ebit_margin_ltm`/`da_to_revenue_ltm`/`capex_to_revenue_ltm`/`cost_of_debt` 各比率的 LTM 分母。

**`revenue_base` — 最后年报营收 · 亿元** · `data` · 进引擎
- 怎么取：年度序列里最大年份那一行的营业总收入（`max(annual)` → `revenue_annual[year]`）。
- 为什么不直接用 `revenue_ltm`：增速路径是**逐年递推**的，需要一个「上一整年」的起点，LTM 混着两个财年的尾巴会让第一年增速虚高。
- 作用：`revenue_path` 的递推起点，也是显性期第一年 ΔNWC 的上年基数（见 §6.3）。

**`revenue_cagr_5y` — 近 5 年营收 CAGR · pct** · `data` · 参考行
- 怎么取：`cagr(年度营收序列, 5)`。
- 为什么留一行：它是「完全没有研报覆盖」时的回退锚（`build_growth_path` 的 `fallback_growth`）；同时给人一眼看出增速路径是不是被某个异常年份带着走。
- 作用：只在回退链里被读，正常情况下不参与定价。

**`anchor_source` — 收入锚点来源 · 文本** · `estimate` · 参考行
- 怎么取：有任一年一致预期营收 → `一致预期`；一年都没有 → `历史CAGR回退`。note 里写覆盖机构家数。
- 为什么：整个收入预测的**方法论**只有这两种，面板必须让人一眼看到这次用的是哪一种——两种情况下同一格数字的可信度不是一回事。
- 作用：说明行，不定价。

**`consensus_revenue` — 营收一致预期 · 亿元（year-map）** · `estimate` · 进引擎
- 怎么取：`yctj_list` 里 `YEAR_MARK="E"` 的年份，取 `TOTAL_OPERATE_INCOME`；只保留非空年份。`confidence = min(1, 机构家数 ÷ 30)`，机构家数读 `TOTAL_OPERATE_INCOME_COUNT`。
- 为什么用它而不是自己的 extrapolation：分析师共识是市场对下一年的定价信息，模型没有理由假装自己更强；但它**只在覆盖到的年份**被当锚点，缺的年份绝不外推预期。
- 作用：锚点年直接取它的绝对额（见 §6.1）。它不再决定显性期长度——年数是「显性预测期」那一行的输入（§5.6），锚点数只参与定下限。人工改过上游增速的那一年起（含）它不再钉住营收：数还在这里、面板照常显示，只是不进定价。

**`consensus_dispersion` — 机构 EPS 分歧度 CV · pct（year-map）** · `estimate` · 参考行
- 怎么取：`jgyc` 里逐家机构的分年 EPS（`EPS1..EPS4`），丢掉伪行（`ORG_CODE="00000000"` 以及名称含「平均/一致」的汇总行，它们会把样本数翻倍），逐年算 `标准差 ÷ 均值`；只保留预测年份。
- 为什么用 CV 而非绝对差：分歧度要和跨规模的公司比较；为什么用 EPS 而非营收：`jgyc` 只给逐家 EPS。为什么不做成定价输入：分歧度大≠估值低，把它塞进折现率就成了拍脑袋的风险溢价。
- 作用：给 `consensus_revenue` 那句「覆盖机构 18 家」配上可信度的可视化证据；越大越该怀疑锚点。

**`revenue_growth_path` — 营收增速路径 · pct（year-map）** · `estimate` · 进引擎
- 怎么取：见 §6.1，锚点年用 `预期营收 ÷ 上年营收 − 1`，其后逐年线性回落到级联永续 g。
- 为什么用增速而非直接给绝对额路径：人改「2029 年增速 +2pp」是有意义的操作，改「2029 年营收 1987.4 亿」则不知道自己改了什么。
- 作用：营收绝对额路径的唯一驱动，也是引擎唯一的收入侧输入。人工改过其中任何一年，就从最早被点名的那一年起接管营收，一致预期那些锚点年往后不再钉住绝对额（§6.1）。

**`revenue_path` — 营收绝对额路径 · 亿元（year-map）** · `estimate` · 参考行
- 怎么取：§6.1 的递推结果。
- 为什么它是参考行：它记的是「这个数当时怎么来的」（`DERIVES` 里的建链出处）。盘上的 baseline 不被改数写回，但面板与推导图上这一格由 `recompute` 从 `revenue_growth_path` + `consensus_revenue` + `revenue_base` 当场重导，引擎定价走的也是同一条重算，两处看的数一致。所以它是给人看的中间产物，锁死以免被误当成输入。
- 作用：让「增速路径 → 绝对额」这一跳看得见、可核对。

### 5.2 盈利与税率

**`ebit_margin_ltm` — EBIT 率 LTM · pct** · `data` · 进引擎
- 怎么取：LTM `(OPERATE_PROFIT + FE_INTEREST_EXPENSE − FAIRVALUE_CHANGE_INCOME − 非经常性损益剔除额)` ÷ LTM `TOTAL_OPERATE_INCOME`。分子前三项各自独立滚动成 LTM，缺失或为 0 的那一项调整量为 0，即退回「EBIT＝营业利润」；这一批真正动了 EBIT 的科目与其带符号金额写在行凭证里。剔除额取最近一个整年年报那一笔（不做季度差分，理由见 `normalization_strip`），它本身已不含公允价值变动那一行（EBIT 口径已整行减过它，见 `normalization_strip` 的搬运规则），`--no-normalize` 或该窗口未过护栏时为 0，此时来源列写「调整后 EBIT」而非「正常化后 EBIT」。
- 为什么是这两项调整：营业利润已经扣掉了财务费用里的利息支出，而 WACC 那条腿另外按债务成本给利息计价，不加回来等于同一笔利息扣两遍；只加 `FE_INTEREST_EXPENSE`，不加 `FINANCE_EXPENSE` 净额，因为那个净额里的大头是利息收入，而利息收入对应的现金在资本结构那一档已经按 `CASH_KEYS` 从企业价值里扣过了。公允价值变动收益要剔，是因为它挂靠的资产是交易性金融资产——同样已经在 `CASH_KEYS` 里当现金扣过，留在 EBIT 里就是这块资产计两遍。投资收益与对联营合营企业的投资收益**不在这一步剔**：长期股权投资没有从企业价值里单独扣过，整块剔掉等于把这块价值整个丢掉。资产/信用减值与其他收益也**不在这一步剔**——这一步只管「利息与金融资产计两遍」；偶发与否由 `normalization_strip` 按官方扣非差额判，判出来的金额只按位置份额搬进分子，不做整科目剔除。
- 作用：没有任何券商锚点的批次里，它是 `ebit_margin_start` 的值，并且是整条 `ebit_margin_path` 的起点；有锚的年份路径用平移后的券商口径，这一行不参与。

**`ebit_margin_hist` — EBIT 率近 5 年均值 · pct** · `data` · 参考行
- 怎么取：年度「(调整后 EBIT − 该年非经常性损益剔除额) ÷ 营业总收入」序列的最后 5 个观测取算术平均（`MARGIN_LOOKBACK=5`），分子与 `ebit_margin_ltm` 同一口径，但**逐年各剔各的**，不是一笔均摊。
- 为什么是均值而非中位数或趋势外推：这是**均值回归目标位**，作用是把「周期顶部的高利润率」在显性期末拉回常态；5 年大致覆盖一轮中小周期，中位数会丢掉「这几年确实在滑坡」的信息。
- 作用：`build_margin_path` 的回落终点。

**`normalization_strip` — 非经常性损益剔除额 · 亿元** · `data` · 只读参考行
- 是哪一笔：证监会《监管规则适用指引——解释性公告第 1 号》（2023 修订）定义的「非经常性损益」是**归母、税后**的一个净额，官方口径直接给得出：`S = PARENT_NETPROFIT − DEDUCT_PARENT_NETPROFIT`（归母净利 − 扣非归母净利）。级联吃的是**税前、合并**的营业利润，所以搬运 `S` 需要两个换算，一个都不能省：
  - **税后 → 税前**：反推 `S ÷ [(1 − t)(1 − m)]`，`t = INCOME_TAX ÷ TOTAL_PROFIT`、`m = MINORITY_INTEREST ÷ NETPROFIT`（该字段整列缺失按 0，实测那不是覆盖率缺口而是没有少数股东）。
  - **合并 → 归母**：官方 `S` 只算归母那一份，而营业利润里躺着的是全部；这一步与上一步合成同一个分母，不另开。
- 位置份额 `w`：`S` 从不说明那笔偶发落在营业利润的**上面还是下面**。按科目分两堆——A 堆在营业利润之内（公允价值变动收益、投资收益、资产处置收益、资产/信用减值、其他收益），B 堆在营业利润之外、利润总额之内（营业外收支、非流动资产处置损益）。公允价值变动那一行只留在 A 堆里参与两条恒等式的验算，**不进金额与份额**：级联的 EBIT 已经整行减过它，官方 `S` 仍含这一笔，若再按 `反推额 × w` 搬一次，同一笔 FV 就被从 EBIT 里走了两次（为正时压低、为负时抬高）。所以先把它从反推额里减掉，份额也按剩下的科目重算：`w = max(0, |A 堆| − |公允价值变动|) ÷ (max(0, |A 堆| − |公允价值变动|) + |B 堆|)`，剔掉的是 `(反推额 − 公允价值变动) × w`。当 `S` 全部由 FV 构成时 `反推额 = 公允价值变动`，剔除额为 0，EBIT 保持原值。孪生科目（收益／损失两列）只认出现的那一支，`_LOSS` 取反。`INVEST_JOINT_INCOME` 是「其中：」子项，含它会把同一笔收益计两遍，不入堆。
- 位置靠两条加总恒等式验，不靠信仰：`E1 = 利润总额 − 营业利润 − B堆` ≟ 0、`E2 = 营业利润 − (营业总收入 − 营业总成本) − A堆` ≟ 0，容差 `IDENTITY_TOLERANCE = 0.5% × |EBIT|`。**两条都闭合才认这套分堆**，否则残差本身就是「位置未知」的规模，金额不搬（实测：招行 2024 按孪生科目取反把 E2 从 42.42% 收到 2.24%；含 `INVEST_JOINT_INCOME` 时万科残差 4.948%、中石化 7.032%，不含时两者归 0.0000%）。
- 为什么必须有 `w`：茅台 2018 的 `S` 是 −3.82 亿，主体是 5.27 亿对外捐赠（营业外支出，本来就不在 513.43 亿的营业利润里）。不做位置判断直接把反推额从 EBIT 里扣，EBIT 凭空抬高 **+1.07%**；按 `w≈0.02` 调整后是 **+0.02%**，误差缩小约 50 倍。`tests/test_normalize.py` 按同一比例造了一行钉住这条机制（不做位置判断 **+1.89%**、按 `w` **+0.035%**、相差 53.7 倍）。这组真实报表的数字也能不联网复算：批次 `runs/600519/20261025-193719/raw/income_statement.json` 里那条 `2018-12-31` 的行喂进 `normalize_year`，实测 `t` 25.57%、`m` 6.94%、反推 −5.51 亿、`w` 0.0199、剔除 −0.1096 亿，E1/E2 残差都是 1e-17 量级；这一行公允价值变动为 0，所以新规则（FV 不进金额与份额）不改动上面任何一个数。2018 不在近 5 年的正常化窗口里，所以它不进任何批次的分子，只是一条能对着盘的原始答复重算的样例。
- 为什么只用年报：A 股偶发项年末一次算清，单季 `S` 年内会反号（紫金矿业 2025 四季 2.85／13.82／20.69／−26.83 亿），拿它差分进 LTM 分子等于塞进一个随 Q4 滚入而跳变的阶梯函数。所以近 5 年均值**逐年各剔各的**，LTM 那一档取窗口里最近一个整年那一笔。
- 护栏（任一命中 → **整窗不剔**，两档 EBIT 率退回报表原值，本行凭证写明是哪一年、因为什么）：① 两条恒等式不闭合；② 该年缺扣非归母净利；③ 缺所得税费用，或利润总额／净利润为 0，反推分母无从落地；④ 反推分母 `(1−t)(1−m) ≤ 0`；⑤ 科目两堆均为 0（这笔偶发无处安放，不许小分母抖出满额调整）；⑥ 剔完会把营业利润推过零或推成 0（`(EBIT − 剔除额) × EBIT ≤ 0`）。整窗而非逐年：两套口径混进同一个 5 年序列，回落终点就成了无法复现的混合数。
- **亏损年照样正常化**：正常化是一个减法，不是比率，EBIT 的符号与算术无关。利润总额与净利润同时为负时 `t` 是税盾、`m` 是少数股东的亏损份额，盘上 132 个恒等式闭合的年报行实测 `(1−t)(1−m)` 落在 **0.408~1.198**（中位 0.721），区间稳定；万科 2024 的 −381.87 亿营业利润剔 −35.82 亿后是 −346.05 亿（亏损做窄，方向正确），两条残差均 0.0000%。被第⑥条拦下的次数在这 132 行里是 **0**。
- 谁天生出局：金融股。银行、证券、保险的营业总成本结构让 E2 不闭合（实测 600036 2.32~29.76%、000001 40.39~132.24%、601318 4.15~63.30%、000776 31.71~107.13%），由数据自动挡在门外，代码里没有行业名单。
- 作用与身份：数已经用在 `ebit_margin_ltm` 与 `ebit_margin_hist` 的分子里了，本行只作对照，所以不在 `dcf.ENGINE_INPUTS` 那 31 个键里，面板不给它输入框。`ebit_margin_ltm` 的 `raw(ebit_ltm)` 存的是**正常化之后**的分子（面板改营收时用它重导比率，正常化因此活着），本行的 `raw(ebit_ltm_reported)` 存**未剔**的报表值，两个数并列留档。关掉整组用 `--no-normalize`。
- 已知不完美：位置是**堆级近似**，逐笔明细在年报「非经常性损益明细表」正文里，免登录通道拿不到，所以凭证如实写「按科目楼层分堆」，不假装是逐笔判定（§12 第 6 条）。

**`ebit_margin_consensus` — EBIT 率一致预期 · pct（year-map）** · `estimate` · 参考行
- 怎么取：预期年份 `OPERATE_PROFIT ÷ TOTAL_OPERATE_INCOME`（两者都是一致预期字段），只在分子非空时保留；再把各年整体平移 `机器 EBIT 率 LTM − 营业利润率 LTM` 这一个差，平移到与 `ebit_margin_hist` 同一口径。券商原值与同口径机器营业利润率、平移额一并存在这一行的 `raw` 里。
- 为什么只平移、不做科目调整：券商预测的是营业利润本身，不会给出「下一年的利息费用」与「下一年的公允价值变动」，加回与剔除都无从下手。所以锚定年只能先取券商的营业利润率，再按同一 LTM 期的两口径之差整体挪一下水平；各年之间的相对变化保持券商原样，挪的是整条曲线的高度，不是形状。两期数凑不齐（缺营业利润率 LTM 或 EBIT 率 LTM）时不平移，凭证写明，顶层 `warnings` 加一条「锚点年与回落终点的分子定义不同」。
- 为什么不直接把这一行送进引擎：引擎要的是**路径**，而这一行只覆盖部分年份；路径由 `ebit_margin_path` 承担（它已经把这里的值取过了）。留这一行是为了看清「回落前起点是不是研报给的」。
- 作用：`ebit_margin_start` 与 `ebit_margin_path` 的源头。

**`ebit_margin_start` — 显性期首年 EBIT 率 · pct** · `estimate` · 参考行
- 怎么取：一致预期首年（已平移）的 EBIT 率；缺该年预期时退回 `ebit_margin_ltm`。
- 为什么：首年最容易测错（研报口径调整、并购并表），单独一行让人和机器都盯住它。退回时它跟着正常化口径走，有锚时跟着平移后的券商预测走——两档现在同一口径，来源列写明取的是哪一档。
- 作用：路径的起点（在没有任何预期年份时它是回落的起点）。

**`ebit_margin_path` — EBIT 率分年路径 · pct（year-map）** · `estimate` · 进引擎
- 怎么取：见 §6.2。有预期年取平移后的预期，其余年份从最近一个已知值向 `ebit_margin_hist` 线性回落。
- 为什么路径而不是单一比率：单一比率要么用周期顶部的 LTM（高估），要么用 5 年均值（无视研报对明年的判断）。路径同时承认「短期有研报、长期会回归」。
- 作用：EBIT 的全部来源；缺少年份时引擎按 `_forward_filled` 沿用最近一年。

**`net_profit_ltm` — 归母净利润 LTM · 亿元** · `data` · 参考行
- 怎么取：`GINCOME` 的 `PARENT_NETPROFIT`（累计值）滚动十二个月，与 `revenue_ltm` 同一套期间口径（§4.2）。
- 为什么是归母而不是净利润：市值买的是归属普通股股东那一份，少数股东那份利润不在里面；用合并净利润当分母会把少数股东的盈利算成自己的，市盈率系统性偏低。
- 为什么单独立一行：`pe_ttm` 现在是自算的（§5.6），分母必须看得见、有出处、可复算。这一行与 `pe_ttm` 都不进引擎——2026-10-30 起退出倍数两臂都按 `exit_ev_ebitda` 计价，市盈率那一格只作对照。
- 作用：当前滚动市盈率的分母。缺它（最新报告期与上年同期不齐）时 `pe_ttm` 出不了数，原因写在那一行的凭证里。

**`tax_rate_ltm` — 有效税率 LTM · pct** · `data` · 进引擎
- 怎么取：LTM `INCOME_TAX` ÷ LTM `TOTAL_PROFIT`。
- 为什么不用法定 25%：茅台 15%（西部大开发/高新）、多数科技 15%、部分 25%，用法定值会系统性错估 NOPAT。为什么用利润总额而非税前利润+利息还原：这是比率近似，不做利息抵税的二次调整——那属于 WACC 里 `(1−t)` 的工作。
- 定价用的不是原值：`bounded_tax_rate()` 把定价税率限定在 **0~25%**。LTM 越界（负值来自税收返还/递延调整，高于 25% 来自一次性所得或亏损年度的比率失真）先退回 `tax_rate_hist`；均值同样越界或缺失时按法定 25%。退回原因同时进本行凭证与 `warnings`。
- 作用：`NOPAT = EBIT × (1 − t)`；同时进 WACC 的税后债务成本与 ROIC 的 NOPAT。

**`tax_rate_hist` — 有效税率近 5 年均值 · pct** · `data` · 进引擎（仅兜底）
- 怎么取：年度 `所得税 ÷ 利润总额` 后 5 个观测均值。
- 为什么留兜底：LTM 会因一次性税收返还/递延所得税调整出负值或 60% 的荒谬值；LTM 越界或缺失时用它，它也不可用时按法定 25% 计并**写进 warnings**。
- 作用：税率与级联的最后一道防线。

### 5.3 再投资与营运资本

这三行是「增长要花多少钱」的三项，全部以营收为分母，因为营收是路径里唯一被独立预测的量。

**`da_to_revenue_ltm` — 折旧摊销/营收 LTM · pct** · `data` · 进引擎
- 怎么取：四项折旧摊销（固定资产折旧 + 无形资产摊销 + 长期待摊费用摊销 + **使用权资产摊销**）的滚动十二个月之和 ÷ **同一段十二个月**的营收。
- 窗口尾巴会退一期：这四项编在现金流量表的**补充资料**里，准则只要求中报与年报编那一节，一季报和三季报的行是空的。最新一期恰好是季报时，滚动窗口断在没有披露的那一格，从前整行留空、引擎把 `or 0.0` 当折旧为零（而同一段下面的资本开支却有近五年兜底，两边不对称）。现在按 `periods.ltm(..., anchor=)` 把窗口退到最近真报了数的一期，分子分母同取那段十二个月，锚日与算式写进本行凭证，`raw` 存下锚日、同窗营收与全窗营收三件原料。实测 301190 善水科技 `runs/301190/20261025-165457`（`--from-run` 离线复现，零网络）：退到 2026-06-30，0.5472 亿元 ÷ 9.4242 亿元 = **5.8061%**，同一批证据、同一套代码、只换这一格：`FCFF·Gordon` 19.9098 → **25.8514** 元/股（+29.8%）、`FCFF·退出倍数` 42.9711 → **52.1448**（+21.3%），`exit_ev_ebitda` 那格从 44.07 降到 28.21（EBITDA 的分母补回了折旧），两法差距从 2.16 倍收到 2.02 倍。
- 分母为什么跟着退：比率的两边必须是同一段。拿全窗营收（同一批是 9.7028 亿元）去除退锚的分子会得 5.6396%，那是一个不属于任何十二个月的数。面板改「营收 LTM」时缩放的是那段窗口营收（缩放比例按全窗营收的变化算，见 `raw.revenue_ltm`），所以这条边仍是活的、又不会变成跨窗口相除。
- 退无可退的那种：整张现金流量表根本没有补充资料（银行、保险、证券——盘上 600036／000001／000776／601318 的批次都是这一种，`raw/cash_flow.json` 里 `result` 就是 `null`）。本行照旧留空，凭证写「四项从未披露」。这不修：同一批里 `capex_to_revenue_ltm` 与 `nwc_to_revenue_level` 也全空（这类公司的资产负债表没有应收票据、存货与预付款项，`_nwc` 在应收那一组取不到任何一个非空键就返回 `None`），`FCFF = NOPAT + D&A − CapEx − ΔNWC` 的后三项一起为零，误差同向相消，给这类公司硬造一个折旧额反而更错。
- 为什么含使用权资产摊销：本口径把租赁负债计为有息负债（见 §5.4），租赁的本金流出已经通过「租赁净融资」在 FCFE 侧处理（只覆盖非流动部分，边界见 §5.4 与 §12 第 7 条），FCFF 里不再扣租赁本金；那么损益里对应的使用权资产摊销就必须加回，否则同一笔钱被扣两次。
- 作用：`FCFF = NOPAT + D&A − CapEx − ΔNWC` 的加回项；同时是隐含 EV/EBITDA 里 EBITDA 的一半。

**`da_to_revenue_hist` — 折旧摊销/营收 近 5 年均值 · pct** · `data` · 参考行
- 怎么取：年度 D&A ÷ 营收的后 5 个观测均值。
- 为什么留而不进引擎：折旧是刚性合同，不像 capex 那样有强周期，LTM 已经足够稳；留这一行是为了判断 LTM 是否被某年大额摊销扭曲。
- 作用：对照证据。

**`capex_to_revenue_ltm` — 资本支出/营收 LTM · pct** · `data` · 进引擎
- 怎么取：LTM `CONSTRUCT_LONG_ASSET`（购建固定资产、无形资产和其他长期资产支付的现金）÷ LTM 营收。
- 为什么用现金流量表而非「固定资产净额变动」：账面变动 = 支出 − 折旧 + 在建转固 + 收购并表 + 处置，用净额当 capex 会把折旧算两遍并把并表当投资。现金流量表的口径就是「今年真花了多少钱」。
- 作用：FCFF/FCFE 的扣项；与 D&A 的比值决定「维持性 vs 扩张性」。
- 已知偏差：LTM 把一年里的资本开支节奏（季末集中付款、在建工程跨期）摊平了。

**`capex_to_revenue_hist` — 资本支出/营收 近 5 年均值 · pct** · `data` · 进引擎（仅兜底）
- 怎么取：同上，年度后 5 均值。
- 为什么 capex 需要 5 年均值而 D&A 不需要：capex 有强周期（中石化的大项目年、白酒的产能扩张年），单看 LTM 会把周期高点当永续资本强度。引擎只在 LTM 缺失时才用它。
- 作用：兜底 + 给人眼判断 LTM 处在周期哪一段。

**`nwc_to_revenue_level` — 营运资本/营收 近 5 年加权 · pct** · `data` · 进引擎
- 怎么取：
  ```
  NWC = (应收票据及应收账款 或 应收账款，取其一) + 存货 + 预付款项
        − (应付票据及应付账款 或 应付账款，取其一) − 应交税费 − 合同负债 − 应付职工薪酬
  逐年比率_y = NWC_y ÷ 营收_y                    （年报，两者都给得出数的那几年）
  比率 = Σ(权重_y × 逐年比率_y) ÷ Σ权重_y        （最近五年，权重从 1 到 5，最近一年 5）
  ```
  逐年比率与权重逐年写进这一行的凭证，加权结果跟在句尾。
- 为什么每对科目只取一个值：东财 `GBALANCE` 同时给合并科目（应收票据及应收账款）和它的子科目（应收账款）。把它们相加会把应收账款算两遍，足以让营运资本符号翻掉——这是实际踩过的缺陷（`P1-缺陷 营运资本重复计入合并科目与子科目`），所以现在按组取「第一个非空键」。
- 为什么把合同负债、预付款项、应付职工薪酬也算进来：这三项都是经营性的资金占用或资金来源。合同负债是客户先付的钱，随营收增长本身就是一笔经营融资，漏掉会把营运资本占用算大。其他应付款、其他应收款、合同资产没有算，原因是东财 `GBALANCE` 在盘上 60 个批次的这些键全是空值，加不进来；这不是口径选择，是数据缺口。合同负债这个科目自 2020 年新收入准则起才有，更早的年份叫预收款项，本口径没有把预收款项映射过来——近五年窗口落在 2026 年批次上是 2022 年以后的年份，不受这条影响。
- 为什么用「÷ 当年营收」的逐年水平比，不用「÷ 营收变动」的差分比：差分比是两个年度差额相除，分母是那一年的营收增减量。营收下滑的年份分母为负，一笔增加占款的余额变动就被除成负系数；营收几乎平流的年份分母接近零，同一个系数会被推到几十倍。这两个数都会乘到只涨不跌的预测增量上（见 §6.3 的式子），符号一翻就是「营收越增长现金回笼越多」，量级一大就是把几十亿的占用压进一年。实测两批（同一份 `raw/`，只换算子）：600519 近五年逐年水平比全是正的 3.10%～21.04%，而差分比是负的，2025 那一格是 (362.02 − 297.24) ÷ (1,720.54 − 1,741.44) = 64.78 ÷ −20.90 = **−3.10**（营收下滑 20.90 亿、余额上升 64.78 亿），五格均值 −0.400814 被它拖成负数，十年 ΔNWC 合计 −237.37 亿元。002436 六格更极端：逐年水平比 7.88%～22.98% 全正，2023 那一格的差分比是 **−37.50**，五格均值 −7.564149，十年 ΔNWC 合计 **−1,609.02 亿元**（这家公司 2025 年营收只有 71.95 亿）。
- 为什么权重近大远小（1、2、3、4、5）：五年算术均值让最早那一年与最近那一年同权重，而营运资本结构随着渠道与议价力在变，六年前的比率与当下关系薄。权重按年份线性递增，最近一年是 5、最早一年是 1，权重合计 15。这一档不消掉周期，只是把权重往后挪：最近三年的权重合计 12，全部权重 15，即五分之四落在最近三年。实测 600519：简单均值 12.11%、按营收加权 13.16%、这一档 15.10%、最后一年 21.04%——比简单均值靠近当下，也不像单年那样被某一次的备货或清收主导。
- 为什么不列「营运资本 基期余额」那一行：报表最后一年那一格的余额不进引擎（见下一条）。它只用来核对：余额 ÷ 当年营收就是这一行凭证里权重 5 的那一格，两个数在同一行里能看见，不需要另开一格存。
- 已知限制：比率作用在增量上，报表期初余额与「比率 × 基期营收」的差额从不被消化。600519 加权比率 15.10%，最后年报（2025）营收 1,720.54 亿，隐含期初余额 259.84 亿，报表余额 362.02 亿，报表比隐含多 **102.18 亿**。这一差不进任何一年的现金流：预测期只走增量，历史沉淀的那笔占用既不收回也不再加。若把它按回归处理，首年 ΔNWC 会从这一档的 +3.65 亿变成 −94.87 亿（比率乘首年整年营收 1,768.94 亿减报表余额），按残期折进现金流是 −47.43 亿——选择「首年不回归」就是不把这一笔当成当年的现金回笼（另两档的实测见 §12 第 27 条）。
- 作用：`ΔNWC_t = 比率 × (营收_t − 营收_{t−1})`；比率为负说明报表营运资本余额本身为负（别人压进来的钱多于自己占出去的），营收增长反而回笼现金。盘上 18 只票最新一批里这一档为负的有四只（002242 −15.49%、600028 −4.76%、600408 −14.18%、600825 −54.38%），600519 在这一档是 +15.10%（逐只复算见 §12 第 27 条）。

### 5.4 资本结构与桥

**`cash_and_financial_assets` — 货币资金+交易性金融资产 · 亿元** · `data` · 参考行
- 怎么取：最新资产负债表日 `MONETARYFUNDS + TRADE_FINASSET`。
- 为什么现金只算这两项：本口径不承认「其他流动资产里的理财」「存入银行以外的现金等价物」是可自由动用的抵债现金——那是审计口径而非偿债口径。宁可低估现金（估值偏保守）也不把受限资金当钱。
- 作用：净债务的减项（`net_debt` 行已含它，所以这一行本身不定价，用于核对桥的两端）。

**`interest_bearing_debt` — 有息负债 · 亿元** · `data` · 进引擎
- 怎么取：三组的和，每组内部相加：
  ```
  短期借款 + 一年内到期的非流动负债 + 短期应付债券
  长期借款 + 应付债券 + 永续债
  租赁负债（仅非流动部分）
  ```
- 为什么含租赁负债：新租赁准则下使用权资产是融资租入的，租赁负债是真债；把它排除会系统性低估杠杆、抬高分母里权益权重。**一年内到期的租赁负债已经在第一组**，所以这里只加非流动部分，不重复计。
- 为什么永续债算债不算权益：在资产负债表上它是应付项本项；其「股/债」争议留给 `--exclude-lease-debt` 之外的行编辑（人可以把这行改成剔除永续债的值）。
- 为什么 `--exclude-lease-debt` 存在：让租赁口径可切换、可比较，切换时 FCFE 的租赁净融资行同步消失（否则改了债务没改融资，桥不平）。
- 作用：净债务的加项、权益权重的分母、FCFE 的计息基数（`利息 = 当年债务余额 × 税前债务成本`，当年余额 = 报表有息负债 + 净融资 × (s + i)）、ROIC 的投入资本。

**`net_debt` — 净债务 · 亿元** · `data` · 进引擎
- 怎么取：`有息负债 − (货币资金 + 交易性金融资产)`。负值即净现金。
- 作用：FCFF 从 EV 桥到股权价值的减项。注意它**只桥一次**，不进 FCFF 现金流本身。

**`minority_interest` — 少数股东权益 · 亿元** · `data` · 进引擎
- 怎么取：最新资产负债表 `MINORITY_EQUITY`。
- 为什么要减：FCFF 折出来的是「全部投资人」的价值，而合并报表里有两块不属于母公司股东——少数股东的权益（存量）和它的损益（流量，见下一行）。不做这一步就是把子公司 30% 的股权卖给了母公司股东。
- 作用：EV → 股权价值的第二个减项。

**`minority_profit_ltm` — 少数股东损益 LTM · 亿元** · `data` · 进引擎（仅 FCFE）
- 怎么取：利润表 `MINORITY_INTEREST`（少数股东损益）的滚动十二个月。
- 为什么 FCFE 要它：FCFE 从合并口径的 EBIT 出发，税后净利里含着少数股东那一份；不扣掉，折出来的就是「母公司与少数股东共同的」股权现金流，再把整份价值安到母公司股东头上。FCFF 折的是全投资人的钱，不扣。
- 作用：按 LTM 占营收比逐年从税后净利里扣掉；Gordon 的永续分子取末年的 FCFE，这一扣已经含在里面。UEM 与退出倍数两格的终值是企业口径，走的是终止年过桥（减少数股东权益余额），不重复读这一行。
- 缺失时：引擎在 FCFE 下报警并按 0 计；FCFF 不报警。老批次没有这一行就是这个形状。

**`net_borrowing` — 净债务融资 · 亿元** · `data` · 进引擎（仅 FCFE）
- 怎么取：LTM `取得借款收到的现金 + 发行债券收到的现金 − 偿还债务支付的现金`。
- 取数：三笔都取现金流量表主表。发债走 `periods.ltm_flow`——滚动窗口里没报数的期次按 0 计，因为现金流量表的空格表示这笔现金没发生（东财对没有发生的筹资项目留空而不写 0），严格滚动会把 002156 这十二个月的 5.00 亿发债判成缺失。借款与偿债沿用严格滚动，滚不出来时按 0 计（等于这一腿没有融资）。「偿还债务支付的现金」本来就同时覆盖借款与债券本金的偿还，收付两边配平。
- 为什么 FCFE 要它、FCFF 不要：FCFE 是「还完债、借到新债之后落到股东手里的钱」，债务净增是股东的现金流入；FCFF 是全投资人的现金流，借款同时增加 FCFF 的融资来源，不应出现在经营侧。
- 作用：FCFE 公式末尾的加项，同时抬高显性期每一年的计息基数；也是两条口径互相校验时的「合法背离」来源。
- 已知边界：其他筹资两项（`RECEIVE_OTHER_FINANCE` / `PAY_OTHER_FINANCE`）不计入。它们混着回购、处置子公司与其他单位的往来款，方向不代表真实债务；600519 最近一批的 29.00 亿支出与分红无关（分红单列在 `ASSIGN_DIVIDEND_PORFIT`，同期 350.44 亿），性质查不到。`FINLEASE_OBTAIN_FA` 也不计入：它在东财答复里与「融资租入固定资产」并列，是补充资料里的非现金事项。

**`lease_financing` — 租赁净融资 · 亿元** · `data` · 进引擎（仅 FCFE，且随 `--exclude-lease-debt` 消失）
- 怎么取：最新资产负债表日租赁负债（非流动） − 去年同一季末的同科目值。
- 为什么需要它：既然把租赁负债计为债务（§5.4），那 FCFE 就必须把它当债务融资对待——租赁负债**增加**意味着今年用租赁「借」到了一笔设备使用权，是可支配现金流入；减少则是隐含偿还。少了这一行，租赁在分子被当债务计息、在融资侧又被当费用扣，两次惩罚同一件事。
- 已知边界：只用非流动部分做差分，一年内到期部分的变动不在这一行里。免登录的东财三表没有租赁负债的流动/非流动拆分，也没有「偿还租赁负债本金」字段；`NONCURRENT_LIAB_1YEAR` 里混着长期借款的一年内到期部分，不能单独归给租赁。实测最近一批：600408 本行 −0.84 亿、使用权资产同比 −14.36%（反推减少约 0.69 亿）；603906 +0.36 亿对 +1.32 亿；600519 −0.26 亿对 −0.19 亿；600172 −0.56 亿对 −0.44 亿；300308 +0.87 亿对 +1.26 亿。没有改用「使用权资产余额变动」当代理：它等于新签租赁减摊销，分辨不出处置与减值，600408 与 600172 反推出的新签使用权资产分别为 −0.54 亿与 −0.03 亿，为负说明租约收缩或终止时代理会反向失真。FCFF 一侧的对应近似也保留：资本开支只算购建长期资产，新签租赁取得的使用权资产不计入，而折旧摊销含使用权资产摊销——租约稳定时两者大致相抵，扩张时 FCFF 偏高、收缩时偏低。

**`roic_ltm` — LTM ROIC · pct** · `data` · 进引擎
- 怎么取：
  ```
  NOPAT = 调整后 EBIT（§5.2） × (1 − 定价有效税率，见 §5.2 的 0~25% 区间)
  投入资本 = 所有者权益合计 + 有息负债 − (货币资金+交易性金融资产)
  ROIC = NOPAT ÷ 投入资本
  ```
- 为什么这样拼投入资本：它是「投资人实际垫进去的钱」——股东权益加有息债减闲置现金。用账面净资产而非市值，因为 ROIC 要与**经营回报**比，而市值会把未来的预期折进分母，形成自我循环。
- 作用两处：(1) UEM 终值的再投资率 `= g ÷ ROIC`；(2) 警告「ROIC < 折现率 → 增长毁灭价值」。UEM 在 ROIC 非正时直接不出数（`UEM 需要正的 ROIC`）。

### 5.5 折现率

级联顺序：`risk_free` + `beta` × `erp` → `cost_of_equity`；`equity_weight` × CoE + `(1−w_e)` × `cost_of_debt_pretax` × `(1−税率)` → `wacc`。

**`risk_free` — 无风险利率 10Y 国债（级联采用）· pct** · `data`/`convention` · 进引擎
- 怎么取：akshare 中美国债收益率序列的「中国国债收益率10年」列，最新观测为**即期**，近 5 年日频均值为**中枢**；`--risk-free-basis` 在两者间择一（默认 `norm` 中枢），另一行只作对照。东财该列是百分数刻度（`1.6829` 即 1.6829%），所以除 100 是无条件的。
- 为什么默认中枢：即期跟着利率周期走——2026 年 9 月的 1.68% 处在十年最低位，直接进 CAPM 会把折现率压到只比永续增速高一点，Gordon 的 `1/(r−g)` 就成了估值本身。中枢把这段周期摊平。为什么中枢不敢乱用：样本一短，「中枢」只是换了个名字的即期值，所以设了两道下限（窗口内 ≥1000 个日频观测 ≈ 4 个交易年，且跨度 ≥4×365 天），越界就不出中枢、退回即期并把原因写进基准名。
- 护栏：读数 >25% 判定「列单位疑似已改变」，宁缺毋滥。
- 作用：CAPM 的截距。取不到就留空，级联结果回退到基线存量（绝不凭空给一个数）。

**`risk_free_spot` / `risk_free_norm` — 即期 / 近 5 年中枢 · pct** · 参考行
- 怎么取：同源同一次快照的两个统计量；`source` 里记序列名、窗口、观测数与首末日期。
- 为什么两个都留在链上：估值只能取一个进 CAPM，但只看到其中一个的人无从判断它偏在哪一侧。
- 作用：对照；要换基准就改级联那一行（或 `--risk-free-basis`）。

**`beta` — 贝塔 · 倍数** · `data`/`convention` · 进引擎
- 怎么取：最新 156 周（3 年）个股周收益对基准指数**周收益**的 OLS 斜率，指数的市场腿与 ERP 同一条：有全收益孪生（`prices.TR_SYMBOLS`）就用孪生序列，孪生没取到或该基准没有孪生才退回价格指数，走的是哪条腿与原因写进行凭证。周收盘 = 每个 ISO 周内最后一个有效交易日的前复权收盘价；相邻两周的收盘日相隔 >10 天视为停牌跳步，丢掉这个收益（不把一个跨假期的跳步当周频收益）；个股与指数取交集。默认基准 `932000` 中证2000（`--benchmark` 可换 000905 中证500、000906 中证800、000300 沪深300、上证、深成、创业板指；932000 新浪没有日线历史，自动改走中证官网）。
- 为什么实测照用、不「调整回 1」：用一个编出来的 1.00 替换实测值，制造的错误比它避免的多。样本只有 30 周、R²=0.02、β=0.15 这些「数值不好看」的情况一律照用，证据（周数、R²、t 值）写进 note 由人判断。
- 为什么 β≤0 拒绝出数：β 非正会把股权成本压到无风险利率以下，越负越接近翻号，Gordon 的 `1/(r−g)` 直接失真——这不是「数值不好看」而是**算术不成立**，所以抛 `BetaNotApplicable`，整条建链失败（`--beta` 是唯一出路，且人工值也必须是正数）。回归窗口一短测到的是风格背离：2025~2026 中证500 +12% 而茅台/中石化各自下跌，两家 52 周 β 都是显著负值。
- 为什么区分三种失败：`TickerUnavailable` = 名录里就没有这只票（已退市／从没上市／代码写错），一次网都不上，出路只有核对代码或刷新名录；`PricesUnavailable` = 联网了却没取到行情（代码已退市但名录还新/行情源抖动，该核对代码或重取）；`BetaNotApplicable` = 数拿到了但在这个数上折不出发。给前两者建议 `--beta` 是误导——给一只不存在的公司填贝塔，是把「没有这家公司」读成「有这家公司，只是行情缺一段」。
- 已知偏差：前复权价随每次除权重排基准化，所以 β 只在**本批次价格快照**内可复现——这正是价格快照必须落盘的原因。默认基准 932000 只有 2023-08-11 之后的真实行情，而 156 周窗口实测落在 2023-09-01~2026-10-14：整段都在发布日之后，指数腿没有吃到官网的回算段（窗口跟着取数日往后推，这个余量只会越来越大）。
- 作用：CAPM 的斜率；FCFE 估值里唯一影响折现率的系统性风险度量。

**`erp` — 股权风险溢价（级联采用）· pct** · `data`/`convention` · 进引擎
- 怎么取：**realized 历史超额收益**，不是 implied。市场组合用 `--benchmark` 那个指数（默认 `932000` 中证2000）——和 β 回归同一个指数、同一条全收益腿，两个参数才描述同一个市场。取数层 `market.py` 拉的腿：基准指数收盘（价格指数）、它的**全收益孪生指数**（`prices.TR_SYMBOLS`：000905→`H00905`、000906→`H00906`、932000→`932000CNY010`、000300→`H00300`，中证官网口径），以及**同一份 `risk_free` 快照**（不另取一条国债序列）。窗口锚在各条腿**最后一个共同观测日**，不是「今天」，这样 `--from-run` 复现出的数与当场一致。级联用近 3 年窗口（`ERP_CASCADE_WINDOW`）：
  ```
  base_day   = 窗口起点之前最后一根收盘所在日
  T          = (end_day − base_day) 天数 ÷ 365.25
  年化总收益 = (末日全收益 ÷ base_day 全收益)^(1/T) − 1
  erp        = 年化总收益 − 同窗口 10Y 国债中枢
  ```
  这个指数没有孪生（000001/399001/399006，以及任何自己填进来的代码）或孪生取数失败时，走降级路：`erp = 年化价格涨幅 + 股息腿 − 同窗口 10Y 国债中枢`，股息腿＝窗口内每天取（沪 A + 深 A）可得上腿的均值、再对全窗口求均值。**走的是哪条腿记在 `windows[].market_leg`（`total_return` / `price_plus_dividend`），note 里也点名**，两条路的数不混在一起看；乐咕只在降级路被调用，主路下凭证里明写「未取股息率」及其原因。
  「今年以来」的窗口起点是 `end_day` 那一年的 1 月 1 日，所以基数是去年最后一根收盘，不会漏掉 1 月的涨幅。
- 为什么优先全收益：CAPM 要的是持有股权的**总**回报补偿，只用价格指数会系统性低估（A 股股息率 2%~3% 就是被丢掉的那一块）。全收益指数在除权日就把分红再投资进点位，口径天然完整，顺带消掉「分红腿是全市场而非指数成分」这层杂质；它仍是**税前**口径（红利税不计），所以严格说是总回报的上界。**β 与 ERP 现在共用这一条腿**：回归的分子与分母都换成全收益周收益，市场组合的定义在两处一致；孪生没取到或该基准没有孪生时，两边一起退回价格指数（ERP 那侧另加股息腿），行凭证写明用的是哪条腿。
- 为什么默认档是「932000 + 近 3 年」：市场组合选谁本来就是研究判断，这一次的判断是「A 股绝大多数个股的市值落在中证2000 的区间里，小盘宽基才是那把尺子」；取数边界替它定了窗口。① 932000 在 `TR_SYMBOLS` 名单里，市场腿是全收益口径，免掉「分红腿是全市场而非成分」那层杂质。② 这家指数由中证在 **2023-08-11** 发布，官网交来的日线却一路回到 2015-10-14——发布日之前那八年是**回算段**（§12.10），而取数层分辨不出真实行情与回算。近 3 年（2026-10-14 批次的窗口 2023-10-13~2026-10-14）于是成了这家基准唯一「整段都是真实交易历史」的窗口：近 5 年的头 1.8 年、近 10 年的头 7.8 年都是回算数。③ 实测 **+6.90%** 落在 `ERP_RANGE` 内，默认口径因此不再天天产出「退回惯例 6%」那条警告（旧档 000905 + 近 5 年实测 −0.26%，天天有）。窗口清单与级联档都在 `assumptions.py` 一处，换档时参考行与窗口下拉自动跟着换。
- 无风险腿按各自窗口求中枢：`_risk_free_leg` 把窗口锚在国债序列**最后一个观测日**往前推整 N 年求中枢（round 到 6 位，与 `macro` 同规矩），窗口跨度与请求长度差不到一天，所以「N 年超额」减的一定是 N 年的国债均值，而不是以行情末日为锚的另一段均值；今年以来没有「中枢」可言，取本窗口均值并在 `risk_free_basis` 点名。**但级联档改成近 3 年之后，ERP 的减数（3 年中枢 1.97%）与 CAPM 里那一格 rf（`risk_free_norm`＝5 年中枢 2.29%）不再是同一个数**——旧口径（近 5 年）下两者逐位相同，现在这条同一性只剩在 `erp_5y` 参考行上。混搭记在 §12.1，不消掉它是因为 `--risk-free-basis` 的两个候选都出自 `macro` 的固定窗口，跟着 ERP 窗口漂移会让 rf 行失去意义。
- 已知口径不纯（写进 note，不藏）：降级路的分红腿是**全市场** A 股股息率，不是该指数成分的分红；两条路都另给 `erp_price_only`（不含分红的超额），让人看得见分红腿值多少个 bp。
- 护栏：每类腿都有下限——收盘 ≥ 每年 100 个观测、rf ≥ 100 个、窗口跨度占满 ≥75% 且 ≥60 天；股息率 >10%、rf >25% 判定「列单位疑似已改变」。**级联还要求结果落在 `ERP_RANGE = 0%~15%`**：窗口整体下跌时超额为负，CAPM 会折出低于无风险利率的股权成本，那已经不是风险定价；牛市尾巴年化出的两位数也不该当永续补偿。任一越界就沿用惯例 `6.0%`，并把**被拒的那次实测值和原因**写进基准名与 note（与债务成本、永续增速同一套纪律：兜底值留着，但要说清这一格仍是猜的）。全收益为负是这条下界最常触发的一档，而它触发得多常见，取决于默认档落在哪家指数、哪个窗口上：旧的默认组合（000905 中证500 + 近 5 年）实测 −0.26%，那一行常年是惯例 `6.0%`、每次建链都上一条警告；换成 932000 + 近 3 年之后实测 +6.90%，默认口径不再有那条警告，兜底与告示改由「换基准后近 3 年也为负」那种批次触发（面板上仍可把级联档手动换成别的窗口，见 §4.4 的 `warnings` 纪律）。
- 取不到数**不炸链**（与 `price_history` 相反）：市场快照缺失只让 ERP 回退惯例值，因为 β 那一腿还要用行情，而 ERP 有可解释的兜底。凡是「回退了惯例值」或「孪生没取到」，除了行内 note 还要在 `baseline.json` 顶层 `warnings` 里留一条可见告示（见 §4.4）。
- 没有 `--erp` 命令行开关：要按别的窗口或别的数值定价，直接改这一行（面板可编辑、会被定价）。
- 作用：β 的乘数，`CoE = rf + β × erp`。低 β 票上它是折现率的主要来源——β≈0.4 时 erp 每动 1 个点，CoE 动 0.4 个点。

**`erp_ytd` / `erp_5y` / `erp_10y` — 今年以来 / 近 5 年 / 近 10 年超额收益 · pct** · 参考行
- 怎么取：与级联行**同一个式子**，只是换窗口；同一份快照、同一个共同观测日锚点，四行互为对照。参考行是「四个窗口里除去级联那一档」自动导出的，级联档一换，参考行的 key 与名字跟着换。
- 为什么三行都留在链上：realized 口径对窗口极敏感。2026-10-14 那批以 932000 全收益为市场腿实测，今年以来 −10.58%、近 3 年 +6.90%、近 5 年 +3.51%、近 10 年 −2.07%——只看一个窗口等于替市场挑了叙事。
- 作用：纯对照，**不在 `ENGINE_INPUTS` 里**，改它们不动结果（面板登记为未定价改动）。推导图里它们是孤立根节点：级联走的那一档在链上的 key 是 `erp` 而不是 `erp_3y`，所以没有画一条假的 `DERIVES` 边。

**`cost_of_debt_pretax` — 税前债务成本 · pct** · `data`/`convention` · 进引擎
- 怎么取：`利息费用 LTM（FE_INTEREST_EXPENSE） ÷ 平均有息负债`，平均 = (本期 + 上年同期) ÷ 2；缺上年同期（上市不满两年）就退化为期末单点，并在 note 里说明退化了。
- 为什么分子用「财务费用下的利息支出」而不是财务费用净额：财务费用是净额，茅台为负（存款利息抵过了借款利息），拿它当分子会算出负债务成本。
- 为什么带护栏：分母一小比值就变噪声——茅台平均有息负债 2.6 亿（几乎全是租赁负债），0.45 亿利息费用能算出 17.7% 的「债务成本」。三道护栏：分母 ≥ max(1 亿, 营收×0.5%)、结果落在 0.5%~12%、分子必须为正。任一越界就不出实测值、沿用惯例 `3.1%`（LPR 附近），并把**被拒的算法原文**写进 note，让人知道这一格仍是猜的。
- 已知偏差：资本化利息不进财务费用，所以在建工程多的公司实测值偏低。
- 作用：WACC 的税后债务项；FCFE 里 `利息 = 有息负债 × 它`。

**`equity_weight` — 权益权重 · pct** · `data` · 进引擎
- 怎么取：`总市值 ÷ (总市值 + 有息负债)`。
- 为什么用市值不用账面权益：WACC 的权重应该是**边际融资成本**的权重，账面权益把几十年前的融资价折进来了。为什么债务端只用有息负债不用总负债：无息的经营性负债（应付账款）已经在 ΔNWC 里处理，再进权重就重复了。
- 已知影响：`total_market_cap` 来自行情，行情降级到腾讯文本时用 `总市值 ÷ 现价` 反推股本；两者都缺时权益权重为空，级联只能回退到基线存量 WACC。

**`cost_of_equity` / `wacc` — 股权成本 / WACC · pct** · `derived` · 不可编辑
- 怎么取：
  ```
  CoE  = rf + β × ERP
  WACC = w_e × CoE + (1 − w_e) × Kd × (1 − t)
  ```
- 为什么引擎每次视图重算而非读存量：`apply_overrides` 直接拒绝对这两个 key 的赋值（报错文案会点名该改哪六行）；`dcf.discount_rates()` 每次从 rf/β/ERP/权益权重/债务成本/税率当场重推，只有当某个**原始项缺失**时才回退到基线存量行。存量行是「级联起点」，不是「结果」——面板显示的结果行如果不同步重算，就会印出一个引擎从未用过的折现率。
- 作用：FCFF 折在 WACC、FCFE 折在 CoE。`--rate` / 面板 `rate` 参数可以强行钉住一个折现率（此时归因表会标注「已强制指定，级联结果未参与折现」）。

### 5.6 终值与口径

**`terminal_growth` — 永续增长率（级联采用）· pct** · `data`/`convention` · 进引擎
- 怎么取：四档实测 + 惯例兜底，`--terminal-growth-basis` 择一（默认 `conservative`）：
  ```
  中枢   = 近 5 年 Σ(营收增量) ÷ Σ(上年营收)      ← 即以上一年营收加权的年均增速
  保守   = 近 10 年最差年度增速 ÷ 2
  乐观   = 历史最好年度增速
  再投资 = 近 5 个财年 (1 − PO) × ROE 的**中位数**  ← Higgins；逐年配对，不是两条序列各取中位再相乘
  进级联 = max(0, 上面择一的那一档)               ← 实测为负就抬到 0，原值留在基准名里
  兜底   = 惯例 2.5%（连续年度增速观测 < 3 个，或该情形缺观测；再投资档缺凭证时同样兜底）
  ```
  年度增速只在**连续**财年之间计算（停牌/借壳重述/上市首年造成的断档不产生增速），否则会把两年变化当一年。
- 为什么中枢用加权而非算术平均：一个小年撬不动大体量年份。为什么保守取最差年的**一半**：一年的休克（茅台 2025 −1.2%、中石化 2020 −28.9%）不该原样永续下去，但也不该被均值抹平。
- 为什么默认档兜底在 0：一家公司年年萎缩是一回事，把萎缩外推到无穷远是另一回事——后者把终值压成负数，还让 g 越过折现率的下界。所以**只有进级联的那一档**被抬：`max(0, 实测)`，`baseline` 里看得见 0，`evidence` 里同时看得见抬之前是多少（`……实测 -0.60% 为负 → 兜底 0`）。两个参考行不抬，它们的作用正是显示级联那一档偏在哪一侧。人工值（`--terminal-growth` 或面板改这一行）不抬也不压：改了就是当常量用，页面不再替你猜。
- 为什么除了这一条不做别的护栏：g 能不能活下来是**引擎**与折现率的交涉（`g ≥ r` 时 Gordon/UEM 直接不出数），在这一层再加个「魔法上限」正好抹掉面板要展示的敏感性。
- 作用：Gordon/UEM 的分母 `r−g`、终值分子 `(1+g)`、**以及显性期增速路径的回落终点**（两者必须同一个 g，否则显性期和永续期会争论「增长到底去哪了」）。

**`terminal_growth_central` / `terminal_growth_optimistic` — 中枢 / 乐观 · pct** · 参考行
- 为什么并列：三情形只有落在同一个序列上才可比；把它们并排摆出来，「保守」这一格到底保守了多少一目了然。注意乐观值多半 ≥ 折现率，直接改级联行会让 Gordon 无解——note 里就是这么写的。
- 这两行是**实测原值**，不享受 0 兜底：茅台这一批的中枢实测为负，级联行显示 0、中枢行显示那个负数，两行同时在场才看得出兜底吃掉多少。

**`terminal_growth_sustainable` — (1−PO)·ROE 再投资增长率 · pct** · 参考行（默认**不**进级联）
- 怎么取：`raw/dividends.json`（东财分红送配明细）× `raw/main_indicators.json` 的 `ROEJQ`。取最近 5 个**已实施现金分配**的财年，逐年配对 `g_t = (1 − PO_t) × ROE_t`，能配对的年份少于 4 个就不叫「稳定分红」，这一档作废而不是硬算；最后取**中位数**。为什么逐年配对：分红率与 ROE 各自取中位再相乘，等于假设「最典型的那次分红」遇上「最典型的那年 ROE」，而这两个数通常不在同一年。
- 分红率的三条读法，每条挡掉一类错数：
  - 分子按**财年求和**、每 10 股 ÷ 10（那一列的单位是「每 10 股派 X 元」）：2024 年起中期分红常态化，茅台 2024 的两行是 `2024-09-30` 的 238.82 与 `2024-12-31` 的 276.73，合计 51.555 元/股；只看年报那一行会少掉一半，分红率就报成 40.3% 而不是 75.1%。
  - 分母**只取 `REPORT_DATE` 为 12-31 那一行的每股收益**：中报的 EPS 是累计数，用它当分母会算出 200% 量级的分红率。
  - 只认 `方案进度` 含「实施」的行：预披露、股东大会通过而未派发的是承诺，不是现金出去。
  - 分红率 > 100% 的年度整年剔除并写在凭证里，不当 100% 截断——它量的是「利润留存下来能撑起多快增长」，一年把当年的利润超派完不是一种留存率。盘上有两种命法：善水科技 301190 批次 `20261022-161331` 的 2023 年派到当年每股收益的 **152.9%**，正好落在最近 5 个已实施分配的窗口里，凭证因此少一年（只剩 2021／2022／2024／2025 四对，中位 +2.75%，那一句是「窗口内剔除：2023 分红率 152.9% 派过了当年每股收益（特别分红）」）；格力电器 000651 的 2020 年是 **107.8%**（2026-10-22 现取，`runs/000651/20261022-174243/raw/dividends.json`），但它已在窗口之外（该批窗口是 2021～2025），所以那一年的剔除是靠不上的——剔不剔只看窗口，不看历史。
- 为什么它天生偏乐观，因此只作对照：`g = (1−PO)·ROE` 说的是**再投资能力**，不是永续期该用的增速。只要 ROE 高于折现率，这条式子就隐含超额收益永续存在，而 Gordon 与 UEM 都要求 g < r——把它直接填进级联行，多半当场无解。2026-10-22 现取的四批同源自证（每批的 `terminal_growth_sustainable` 对同批 `cost_of_equity`）：茅台 `600519/20261022-161331` 中位 **+14.38%** 对 CoE 3.93%（**3.7 倍**，五对是 14.38% / 14.56% / 16.44% / 8.97% / 6.78%）、招商银行 `600036/20261022-174159` **+10.54%** 对 2.88%（**3.7 倍**）、紫金矿业 `601899/20261022-174331` **+17.76%** 对 4.38%（**4.1 倍**）——这三家填进级联行都会当场把终值顶到无解。**但「偏乐观」是这一档的常态不是保证**：善水科技 `301190/20261022-161331` 只有 **+2.75%**，低于同批 CoE 6.79%，因为它 2022 年起的 ROE 从 27.43% 塌到 3～5%，留存比例再高也乘不出增长。所以这一行的用法是「与级联那一档并排看」，不是「拿它替换级联那一档」。
- 查不到分红数据时长什么样：`baseline` 为 `null`（不是 0），级联行与这一行各自把原因写在 `evidence` 里，三种缺法三句文案。**① 这一批根本没存分红表**（2026-10-16 之前的批次，以及从它们 `--from-run` 复现出来的批次）：写「不可用：这批没有分红凭证」——主语是这批，不是这家公司，实测 `600028/20261022-161332`（中国石化实际年年大额分红，只是源批次早于 D1）。**② 这家公司的分红表是空的**：统一写「东财个股分红页查不到这只票的现金分红记录：这一档按无分红处理」。口径由用户 2026-10-22 定：**查不到就当作没有**，不再区分「源答零记录」与「那一趟没取到」——零记录的代码东财返回 `result: null`，akshare 在 `stock_fhps_em.py:167` 会抛 `TypeError`，这两条以前都落成报错串（实测 `688561/20261022-174805` 奇安信），而报错串会把人引去点「强制重取」，可这一行重取一百次也不会有分红表。原始报错改存 `raw/dividends.json` 的 `fetch_error` 键，只给修数据的人看——读法与 `payouts` 都不碰它，所以面板上永远是那句「查不到」。这条在老批次上当场生效：`--from-run` 只是照抄 `raw/`，盘上那份 688561 的旧串原样留着（证据不重写），可复现出来的批次 `runs/688561/20261022-204744` 的 baseline 已经读成「不可用：东财个股分红页查不到这只票的现金分红记录：这一档按无分红处理」。**③ 有分红但配不满窗口**：「最近 5 个已实施分配的财年里只有 N 个配得上年报加权 ROE（需 ≥4 个）」，`skipped` 里逐条记哪一年为什么配不上（缺年报每股收益、有方案但未实施）。三种都不拦路：级联行照旧按营收增速那一套出数，面板这一格显示「—」而不是 0（实测 `688561`、`600028` 两批）。要用这一档定价：`--terminal-growth-basis sustainable`，或在面板直接改级联那一行。

**`exit_pe` — 一致预期市盈率 · 倍数（year-map）** · `estimate` · 参考行
- 怎么取：`yctj_chart` 里 `YEAR_MARK="E"` 的 `PE`。
- 作用：卖方对未来某一年股权倍数的预期，只作对照。退出倍数两臂都按 `exit_ev_ebitda` 计价（§7 ⑥），这一行不进定价；从前 FCFE 那一格首选它、缺末年则退 `pe_ttm`，2026-10-30 起这条退路整段撤掉（§12 第 23 条）。

**`pe_ttm` — 当前滚动市盈率 · 倍数** · `data` · 参考行
- 怎么取：**总市值 ÷ 归母净利润 LTM**（分子见 §5.7，分母见 §5.2），相除后按 2 位取整。分子分母都用报表与行情里的原始金额（元），不是面板上那两个四舍五入到分的亿元数——所以拿显示值手算可能在末位差一点。两条行情通道给的市盈率只写进凭证当对照，不进这一行。
- 为什么不采纳行情给的市盈率：同一个字段名在两条通道上是两把尺子。盘上 67 个批逐个用同批报表复算 `市值 ÷ 归母净利 LTM`（§12 第 20 条有全表）：腾讯通道可算的 41 批里 37 批逐位相等、4 批只差末位 0.01；push2 通道可算的 17 批**一批都不等**（绝对差 0.06～18.78）——那是**动态市盈率**（最新中期归母按 `12/月数` 年化）。降级与否会让同一只票跳数，所以自算的这一个才是可复算的：分子分母都在这张链上、各自有凭证。
- 分母非正（亏损或归母 LTM 滚不出来）时这一行**不出数，也不回退通道原值**——一行上不能同时躺两套口径。原因写在这一行的凭证里，且带上通道原值那个数与它的口径，人看得见、也知道差在哪。
- 为什么留着这一行：它是市场此刻对这块净利润的定价，与 `exit_ev_ebitda`（企业口径）并排才看得出两套尺子差多远。从前退出倍数法的 FCFE 那一格直接拿它当年末倍数，所以「改分母（归母净利 LTM）与改分子（总市值）都要能重定价」是这一行的用处；2026-10-30 起它不进定价，但两条上游边仍在，改那两行时这一格照着重算——面板上那两个数得是同一时刻的。

**`exit_ev_ebitda` — 隐含 EV/EBITDA · 倍数** · `estimate` · 进引擎
- 怎么取：现价反推（reverse-DCF 式锚点）：
  ```
  EBITDA = LTM 营收 × (LTM EBIT 率 + D&A 率)
  EV     = 总市值 + 净债务 + 少数股东权益
  倍数   = EV ÷ EBITDA
  ```
- 为什么用现价反推而不是外部研报倍数：研报给的 EV/EBITDA 常是「目标倍数」，把它当输入等于用结论支持结论；现价反推的倍数只回答一件事——市场此刻给这元 EBITDA 定价多少倍。分母 ≤0（亏损或折旧为零）时不出数。
- 作用：两臂退出倍数法的默认倍数。FCFF 折出来的是企业价值，末年的终值 `= 末年 EBITDA × 倍数` 本身就是企业价值；FCFE 折的是股东的钱，同一个乘积要先在终止年那一刻减掉净债务与少数股东权益才是股东那一份（§7 ⑥⑦⑧）。
- 两个边界：① 这一行的分子分母同源于同一张报表（市值 + 当期净债务 ÷ 当期 EBITDA），所以它天然与「本公司的资本结构」自洽，不必再找可比公司配口径；② 但也因为如此，它是**今天**的杠杆下形成的倍数，而桥上的净债务取的是**终止年**那一刻的数——显性期里持续净债务融资的公司这两处的杠杆会拉开，`net_debt/EBITDA` 的差值写在终值那一格的凭证里（§12 第 23 条）。
- 缺这一行时（老批次、或 EBITDA 反推不出数）引擎退回 `implied_ev_ebitda()` 用同批的市值/营收/EBIT 率/D&A 率/净债务/少数股东当场反推，FCFF 那一格的凭证会写明「退出倍数取当前隐含 EV/EBITDA」。倍数或末年 EBITDA 非正一律拒，报「退出 EV/EBITDA 不可得（倍数缺失或非正）／（末年 EBITDA 非正）」——负倍数配负 EBITDA 会折出一个正终值，两个负号相折这种形状必须拦。

**`horizon_target` — 显性预测期 · 年** · `convention` · 进引擎
- 怎么取：**一个选择，不是测算结果**。默认 `HORIZON_TARGET_YEARS = 10`，出处是评估实务那句「详细预测期的结束以该公司进入稳定经营状态为基准……一般来说详细预测期要在 8–12 年」；改它走 `--horizon 12` 或面板这一行。单位是「年」而非 `亿元`/`pct`，所以输入框是直接的数值框。
- 上下限：`floor = max(HORIZON_MIN_YEARS=5, 锚点数 + 1)`，上限 `HORIZON_MAX_YEARS=12`；**锚点优先于上限**（券商已把绝对额锚给到第 13 年时，宁可行长一年也不切掉一个真实的预期年——切掉的不是插值精度）。填得低于 `floor` 或高于上限都不报错：钳到边界，钳了谁、钳成几年写进 evidence，并在顶层 `warnings` 出声。
- 为什么这里没有「每年回落几个点」的旋钮：**年数是输入，回落幅度是它的输出**——`step = (g_perp − 末锚增速) ÷ (回落年数 + 1)`（§6.1）。同一个 g 在 5 年段上要一年掉 1.72pp，在 10 年段上只掉 0.65pp，所以「加长显性期」买的不是多折几年，而是让回落走得更缓、末年与永续之间那一跳变小。
- 两条护栏只看这个选择本身：一年掉得超过 `GLIDE_MAX_PER_YEAR = 3%` 报「硬着陆」（加长年数／换 g 档／改退出倍数终值），一年几乎不动（< `GLIDE_MIN_PER_YEAR = 0.1%`）报「这家公司早就接近稳态，这些年只是在把永续假设摊开」。两条都只报数、不改数，与债务成本、ERP、rf 那几处同一个做法。
- 作用：不进 `evaluate()` 的算术，它**经重导进定价**——`recompute` 按它现算 `revenue_growth_path` 的年份集合，营收绝对额路径、EBIT 率路径、D&A/CapEx/ΔNWC 一年一年跟着走。老批次基线里没有这一行：改动它会被 `apply_overrides` 拒收，年数一字不变（不重排历史批次）。

**`horizon_years` — 显性预测年数 · 年** · `data` · 参考行
- 怎么取：`revenue_growth_path` 覆盖了几年就是几年，evidence 写「引擎折 N 年（2026–2035），每年变动 −0.65%」这样人话；增速行为空时不给数（`None`）而不是硬报 0。
- 为什么不进 ENGINE_INPUTS：它是路径的**结果**（键集合就是年份集合，改它等于改路径）。要动年数就改上面那一行。
- 为什么它现在是实线：年数从行里就读得出来，`derive_horizon_years` 只要增速行，所以 §4.6 那份「永远虚线」名单里已经把它划掉。从前它是锚点覆盖广度的副产品，那时说它会重算才是骗人。

**`mid_year_discount` — 年中折现 · bool** · `convention`（默认开）· 进引擎
- 怎么取：布尔开关，`--mid-year` / `--no-mid-year`。
- 为什么默认开：现金流全年均匀发生，年末折现把第一年少折了半年（`1/(1+r)^0.5` vs `1/(1+r)^1`），长期复利下系统性低估。为什么仍要留开关：与年末口径的同行/模型可比。
- 作用：折现期 `t = s/2, s+0.5, s+1.5, …` 或 `s, s+1, …`；终值折现期 `t = s + N − 1 − 0.5` 或 `s + N − 1`。`s` 是首年残期（§7 ⑤），批次没有报表截止日时 `s = 1`，此时两组式子就退回 `0.5, 1.5, …` 与 `1, 2, …`。

### 5.7 市场与股本

**`price` — 最新价 · 元** · `data` · 进引擎
- 怎么取：push2 `f43`（`fltt=2` 要小数值，否则价格被放大 100 倍），降级腾讯第 3 位。
- 作用：**只用于算上行空间**，不参与任何价值计算（这是刻意的：现价进估值就是循环论证）。行情全挂时这一行为空，面板显示「行情源均不可用，需人工填入」。

**`total_shares` — 总股本 · 亿股** · `data` · 进引擎
- 怎么取：push2 `f84`（股数）；降级口径用 `总市值 ÷ 现价` 反推。
- 为什么注明「未含潜在稀释」：可转债、股权激励、定增预案都不在这一行，估值用的是当前法定股本。要做稀释就改这一行——它是一个可编辑数字，不是一套隐藏逻辑。
- 作用：`每股价值 = 股权价值 ÷ 总股本`。缺它则链条停在股权价值，每股那一跳不出数（图上不画假节点）。

**`market_cap` — 总市值 · 亿元** · `data` · 进引擎
- 怎么取：push2 `f116`；降级腾讯第 45 位（本就是亿元）。
- 作用：权益权重、隐含 EV/EBITDA 与当前滚动市盈率（§5.6 `pe_ttm`）的分子。注意它是 `price × total_shares` 的独立行情读数而非本地乘积——两者不一致时说明行情源的股本口径不同，这本身就是有用的信号。

## 6. 报表科目的预测值怎么取

披露值只到最新一期；未来每一年的报表数字全是**推导**出来的。三张表的预测逻辑分别是：

### 6.1 营收：锚点年 + 回落年 + 递推

```
anchors = {y: 一致预期营收_y | 有值的预期年份}          # 锚点年
g_y     = anchors[y] ÷ anchors[y−1] − 1                 # 首年用 revenue_base 作 anchors[y−1]
floor   = max(5, len(anchors) + 1)                      # 准则下限与「至少留一年回落」取大
horizon = min(max(floor, 显性预测期), max(12, floor))     # 人的选择（默认 10）；锚点长过 12 时锚点赢
tail    = horizon − len(anchors)                        # 回落年数
last_g  = 末锚点的 g，缺锚时用 revenue_cagr_5y，再缺用 g_perp

对 offset = 1..tail：
    g_{anchor_end + offset} = last_g + (g_perp − last_g) × offset ÷ (tail + 1)   # 线性回落

manual  = 人工点过增速的最早那一年（面板或 CLI 改过 `revenue_growth_path` 里的哪几年）；没改过就没有这一条

营收_y = 锚点年且 y 早于 manual → 直接取 anchors[y]（绝不从递推值改）
        其余年（含 manual 那一年的锚点在内）  → 营收_{y−1} × (1 + g_y)
```

- **锚点年（一致预期年份）**：值来自机构共识，模型只负责换算成增速。
- **人工改过增速就从那一年起让位**：一致预期仍是机器基线——没人在增速上动手时锚点年照旧直接取共识绝对额，一个数都不漂。改过增速之后，最早被点名的那一年起（含）不再取锚，往后各年一路按增速续乘。只放开被点名的那一年是不够的：次年又落回共识绝对额，增速改到多大都只影响一年的现金流。锚点那几行的数继续摆在链上、照常显示，只是从接管那年起不进定价；引擎在顶层 `warnings` 里说出接管从哪一年开始。走的是同一份 `inputs` 内部键（人工年份列表由 `apply_overrides` 记，改别的行时清掉），所以面板改数、CLI override、推导图改数三条路结果一致。
- **回落年（预期回落年份）**：共识覆盖不到、又还没进永续期的过渡年。线性回落而不是台阶式跳水，是因为「末锚增速 → 永续 g」一步跳变会让终值年的现金流与显性期末年突然不连续。
- **年数是输入、每年掉几个点是输出**：`tail + 1` 那个分母就是「一年掉多少」，它由 §5.6 那一行填的年数决定，没有单独的旋钮。面板与 CLI 改年数走的都是 `recompute` 那条重导路，年份集合现算，不是把旧路径拉长或截短。
- **回落的目标位必须等于级联采用的 g_perp**：这样显性期与永续期对「增长要去哪」没有分歧；改 `terminal_growth` 会同时移动终值和路径尾部（面板上能看见这两处一起动）。但**落点不是 g**：`offset` 只走到 `tail`，所以末年离 g 还差最后一步（一个 `step`）——显性期与永续之间那一跳因此永远存在，加长年数做的是把这一跳变小，不是把它消掉。「进入稳定经营状态」在这套代码里的可执行含义就是这一跳足够小。
- 递推里 `running` 一旦为 `None`（缺 `revenue_base` 且缺锚）就整段断供，引擎报「营收路径不完整」而不是补 0。同理，`recompute` 现算年份集合时若有一年算不出数（2026-09-21 那几批还没有「最后年报营收」这一行，第一个预估年没有基数可比），整条边认输、一个数都不动——宁可交出一条短一年的旧路径，也不交出一条短一年却自称是新口径的路径。

600519 一次真实批次（报表截至 2026-06-30，`runs/600519/20261016-224007`）：锚点 2026–2028 的营收一致预期 = 1769.69 / 1859.11 / 1955.24 亿元，换算成增速 +2.86% / +5.05% / +5.17%（首年基数是最后年报营收 1720.54 亿），级联 g = 0.00%。同一份原始答复离线复现（`--from-run … --horizon N`，一次网都没联）：

| 显性预测期 | 回落年 | 每年变动 | 末年增速 | FCFF/Gordon 年中折现每股 | 终值占现值 |
| --- | --- | --- | --- | --- | --- |
| 5 年（旧规则的产物） | 2029–2030 | −1.72pp | +1.72% | 2,406.08（＝该批存档基线，一字不差） | 84.9% ⚠ |
| **10 年（新默认）** | 2029–2035 | **−0.65pp** | +0.65% | **2,672.87** | 72.8% |
| 12 年（上限） | 2029–2037 | −0.52pp | +0.52% | 2,780.27 | 68.7% |

年数每加一年这里约 +2% 每股，加的是「回落走得更缓」那一截，不是凭空多出来的现金流；10 年与 12 年之间只差 4.0%，而 5 年与 10 年差 11.1%——**下限那一侧才是贵的**。最后一列还顺带说清了另一件事：`TV_SHARE_WARNING = 75%` 那条警告在 5 年段上每次都亮（84.9%），改成 10 年就不亮了（72.8%）——「结论高度依赖永续假设」这句，一部分本来就是显性期太短造成的。

同一条通路在估值 CLI 上也走得通（前提是本批基线里有这一行）：`python scripts/run_valuation.py 600519 --overrides '{"horizon_target": 12}'` 交出上面第三行那一列，12 个年份逐行列到 2037；老批次上同一条命令会被修正加载器挡下，话说的是同一件事——「未知假设行 horizon_target，引擎与假设链都不认识这个键」。

上面那张表数的是 51 行的老批次。**2026-10-20 联网真取的那一批（`runs/600519/20261020-210034`，10 个来源、52 行）才是这套口径的当前证物**，同一份原始答复再离线复现两次各换显性期（`--from-run … --horizon 5` → `20261020-210120`，`--horizon 20` → `20261020-210119` 被上限压成 12）：每股 **2,175.71 / 2,411.86 / 2,506.12**，终值占现值 **83.5% ⚠ / 70.4% / 66.0%**，回落幅度 −1.72pp / −0.65pp / −0.52pp 与上表一字不差（锚点增速与 g 没变），差的只是行市——现价 1,331.88 元、rf 与 ERP 都是当天的数，所以绝对水平比 10-16 那一批低一档。两批对照正说明该对照的是什么：**年数动的是回落形状与终值占比，不是某一天的每股价**。12 年那一批顶层 `warnings` 里就一句 `填 20 年超过上限 12 年，按 12 年走`，面板顶部警示条与推导图同一条。

### 6.2 EBIT 率：覆盖年取平移后的预期，其后向近 5 年均值回归

```
平移额 = ebit_margin_ltm − 营业利润率 LTM                    # 同一 LTM 期、同一分母的两个比率之差
已知年 = {y: 预期营业利润 ÷ 预期营收 + 平移额 | 该年有预期}   # 有锚年取平移后的预期
起点   = 已知年非空则 (无预期时的最近已知值) 否则 ebit_margin_start
对已知年之外的每个年份 index = 1..n：
    margin_y = 起点 + (hist_5y − 起点) × index ÷ (n + 1)   # 线性回归
```

- 为什么**不做趋势外推**（回归斜率延伸）：EBIT 率的外推在 5 年尺度上是放大器——把最近两年的偶然走向当成结构性改善，且与 D&A/CapEx 比率的「今年水平不变」假设矛盾。
- 为什么用近 5 年均值作目标位：它是周期均值的最短可信估计（`MARGIN_LOOKBACK=5`）。
- 锚点年与回落终点现在同一口径：`hist_5y` 与 `ebit_margin_ltm` 都按 §5.2 `normalization_strip` 减过非经常性损益，券商档在建链时按同一 LTM 期的定义差（机器 EBIT 率 LTM − 营业利润率 LTM）整体平移过；平移只换水平，各年之间的相对变化保持券商原样。差额、券商原值与平移后的值并列写在 `ebit_margin_consensus` 行的凭证与 `raw` 里（§12 第 6 条）。
- 分母与营收同源：比率作用在**当年预测营收**上，所以营收改动会自动带动 EBIT，不需要重复改。
- 引擎侧的兜底：路径缺少年份时 `_forward_filled` 沿用最近一年，全 0 时报「EBIT 率全为 0，请检查 ebit_margin_path」。

### 6.3 其他报表项的预测：比率不变 × 营收

这三项没有独立路径，它们都是「当年的预测营收 × 一个 LTM 比率」：

| 预测项 | 公式 | 隐含假设 |
| --- | --- | --- |
| 折旧摊销 | `D&A_t = 营收_t × da_to_revenue_ltm` | 资本构成不变，折旧强度随收入同比 |
| 资本支出 | `CapEx_t = 营收_t × capex_to_revenue_ltm` | 维持与收入成比例的投入强度 |
| 营运资本变动 | `ΔNWC_t = nwc_to_revenue_level × (营收_t − 营收_{t−1})` | 增量收入的资金占用比例不变；**首年的上年基数是 `revenue_base`（最后年报营收），不是预测值**；报表期初余额与「比率 × 基期营收」的差额不做回归（§5.3 已知限制） |
| 利息（FCFE） | `利息_t = (interest_bearing_debt + 净融资 × (s + i)) × cost_of_debt_pretax` | 债务余额随每年那笔净融资长大，利息按当年余额计提；不做还旧借新的再融资滚动（这是简化） |
| 债务净融资（FCFE） | `net_borrowing + lease_financing` | 按 LTM 水平年年重复（隐含「今年借的节奏会一直继续」）；显性期里它同时抬高债务基数与利息，永续那一段不再包含它（§7 ⑥） |
| 少数股东损益（FCFE） | `少数股东损益_t = 营收_t × (少数股东损益 LTM ÷ LTM 营收)` | 少数股东分走的那一份利润随收入同比例变化；只有 FCFE 扣，FCFF 不扣 |

D&A 与 CapEx 用同一个营收驱动，意味着 `CapEx > D&A` 的那部分才是真实扩张——这也是 ROIC 警告能与增长质量对上的原因。

## 7. 公式推导：从假设到每股价值

引擎（`backend/model/dcf.py: evaluate`）的全部算术。显性期年份集合就是 `revenue_growth_path` 的键集合。

```
① 收入
   营收_t          锚点年取一致预期，否则 营收_{t−1} × (1 + g_t)；人工改过增速的最早那一年起，锚点让位给递推   §6.1
   g_t            有锚年 = 预期营收÷上年营收−1；无锚年 = 线性回落至 g_perp

② 经营利润
   EBIT_t          = 营收_t × margin_t
   NOPAT_t         = EBIT_t × (1 − t_有效)                    t_有效 = bounded_tax_rate(tax_rate_ltm, tax_rate_hist)

③ 全投资资本现金流（FCFF）
   FCFF_t          = NOPAT_t + D&A_t − CapEx_t − ΔNWC_t

④ 股权现金流（FCFE）
   利息_t          = (有息负债 + 净融资 × (s + i)) × Kd_税前      （i = 0..N−1，当年债务余额）
   税后净利_t       = (EBIT_t − 利息_t) × (1 − t_有效)             （合并口径，含少数股东那一份）
   少数股东损益_t    = 营收_t × 少数股东损益率                     （率 = LTM 少数股东损益 ÷ LTM 营收）
   FCFE_t          = 税后净利_t − 少数股东损益_t + D&A_t − CapEx_t − ΔNWC_t + (净债务融资 + 租赁净融资)

⑤ 折现
   s             = 首年残期 =（12 − 报表截止日所在月）÷ 12，截止日不在预测首年那一年时取 1
                   （一季报后 9/12=0.75、中报后 6/12=0.5、三季报后 3/12=0.25、年报后首年已是下一个整年）
   FCFF_首年      × s                                       （首年只算截止日之后的那一段时间）
   t             = s/2, s+0.5, s+1.5, …, s+N−1.5  （年中折现）  或  s, s+1, …, s+N−1（年末）
   折现因子_t     = (1 + r)^{−t}
   r             = WACC（FCFF）  或  CoE（FCFE）  ；--rate 可钉住任意值
   PV_显性        = Σ FCFF_t × 折现因子_t                   （FCFE 同理）

⑥ 终值（三选一）
   Gordon        TV = FCF_N × (1 + g) ÷ (r − g)                         要求 g < r
                 FCFE: FCF_N = 末年 FCFE − 当年净融资
                       （永续那一段只放经营现金流，否则等于假设债务永远按同一速度增长；
                        少数股东损益已在逐年 FCFE 里扣掉，末年那一笔带着它）
   UEM           再投资率 = clip(g ÷ ROIC, 0, 1)
                 TV = NOPAT_N × (1 + g) × (1 − 再投资率) ÷ (r − g)       要求 ROIC > 0，g < r
                 （g<0 时再投资率取 0：不给收缩中的公司收增长红利）
                 FCFF: TV 就是上面这个企业口径的值
                 FCFE: TV = 上面这个值 − 净债务_终止年 − 少数股东权益
                          净债务_终止年 = 报表净债务 + 每年净融资 × (s + N − 1)
                          （NOPAT 是企业口径的现金流，FCFE 折的是股东那一份，所以和退出倍数一样要过桥）
   退出倍数       EV_N    = (EBIT_N + D&A_N) × EV/EBITDA_倍数            两臂同一把尺子
                 FCFF: TV = EV_N
                 FCFE: TV = EV_N − 净债务_终止年 − 少数股东权益
                          净债务_终止年 = 报表净债务 + 每年净融资 × (s + N − 1)
                          每年净融资 = 净债务融资 + 租赁净融资，与 FCFE 里那笔流入同一个数、第一年同样按残期 s 缩
                 （倍数与末年 EBITDA 都要为正，缺一律拒；与 g 无关，所以 g ≥ r 时仍出数，但会标注「不可比价」）

⑦ 终值现值
   t_终值        = s + N − 1 − 0.5（年中）  或  s + N − 1（年末）；s = 1 时即 N − 0.5 / N
   PV_终值       = TV ÷ (1 + r)^{t_终值}

⑧ 价值与桥
   FCFF:  EV      = PV_显性 + PV_终值
         股权价值 = EV − 净债务 − 少数股东权益
   FCFE:  股权价值 = PV_显性 + PV_终值          （Gordon：显性期按股东现金流折，永续那一段只含经营 FCFE，
                                                净融资已在 ⑥ 的终值分子里剔掉，这里不再桥接；
                                                UEM 与退出倍数：桥已在 ⑥ 里站在终止年那一刻过完，这里不再减）

⑨ 每股
   每股价值      = 股权价值 ÷ 总股本
   上行空间      = 每股价值 ÷ 现价 − 1
```

**为什么 `t_终值 = s + N − 1 − 0.5`**：Gordon/UEM 求出的 TV 是「第 N 期之后那一连串现金流的现值」，站在**第 N 期期末**这个时点上折回 t=0。年中折现下最后一个显性现金流站在 s+N−1−0.5，TV 也站在同一时点，两者才可比——所以显性期与终值用同一个折现指数，而不是多算半年。

**为什么首年要乘残期 s**：折现轴的 t=0 是报表截止日，因为桥接项（净债务、少数股东权益）就是那一天的余额。预测首年通常已经走过几个月，那一段的现金流已经变成截止日账上的货币资金或已偿还的债务，再折一遍就是把同一笔钱数两次；所以首年只按剩下的整月计（金额与折现期同时缩），其余各年是完整年度。600519 这批（中报截止 2026-06-30，s=0.5）实测：显性期现值 8,794.12 → 8,521.07 亿（首年只剩半年，现值 −427.42 亿；其余九年因窗口缩短而抬回 +154.37 亿），终值现值 20,930.20 → 21,337.60 亿（整条轴往前挪半年），每股 2,411.74 → 2,422.48（+0.45%，r = WACC 3.93%）。三季报后的票 s=0.25，首年只留一个季度，差额比这批大得多。

**为什么 FCFE 不桥净债务**：FCFE 分子已经扣掉税后利息、加回债务净融资，折出来直接归属股东；再减一次净债务就是把债还了两遍。这句话对 Gordon 成立——它的终值分子是「末年 FCFE − 当年净融资」，股东现金流里只留经营那一段，净融资属于显性期、不进永续（否则等于假设债务永远按同一速度增长）。UEM 与退出倍数两格是例外：UEM 的分子是 NOPAT、退出倍数是 EBITDA × EV/EBITDA，两个终值都是企业口径，所以必须过一次桥——桥要站在**终止年那一刻**过，不能拿报表那天的余额：显性期里每年那笔净融资已经作为股东的现金流入发进 FCFE，它在账上欠着的部分只有在这里减回去，才不会白拿借款的好处。流量与存量各管一头：`每年净融资` 是流量，加进每一年的 FCFE，也抬着那一年的利息；`净债务_终止年 = 报表净债务 + 每年净融资 × (s + N − 1)` 是存量，只在桥上出现一次。少数股东权益没有可累加的变化量（模型里只有报表余额），所以它沿用余额，与 FCFF 那条桥同一个近似。少数股东损益则相反，它是流量，逐年从 FCFE 的税后净利里扣掉——Gordon 的末年流量已经带着这一扣；UEM 与退出倍数两格的终值由 NOPAT / EBITDA 拼成，本来就不含少数股东份额，终值处减的是权益余额，不重复扣。

**引擎的拒绝与警告**（都进 `warnings`，面板与 CLI 照原样显示）：
- 直接不出数（早退）：无增速路径 / 营收路径不完整 / 缺折现率 / `g ≥ r`（Gordon、UEM）/ UEM 缺正 ROIC / 退出倍数不可得（倍数缺失或非正，或末年 EBITDA 非正）/ `g ≤ −100%`。
- 出数并标注：终值占现值 > 75%（`TV_SHARE_WARNING`）；`0 < r−g < 3%`（`THIN_SPREAD_WARNING`，会写明「把最后一期现金流放大了 1/价差 倍」）；退出倍数法下 `g ≥ r` 的「不可比价」提示；`ROIC < r` 的增长毁灭提示；显性期出现负 FCFF；股权价值 ≤0。
- 输入缺失按 0 计、同时报警：折旧摊销占营收、营运资本占营收比率、税前债务成本、有息负债、净债务融资（只在 FCFE 下报）、少数股东损益（只在 FCFE 下报）这几项为空时，引擎仍出数，但对应的一项按 0 参与，`warnings` 逐条说明是哪一项。资本开支占营收 LTM 缺失时先退回历史均值并说明，历史均值也没有才按 0 计。租赁净融资为空不报警：没列租赁负债的公司这一格本来就是空的，按 0 计就是「没有租赁融资」。
- 定价税率越界也出声：LTM 有效税率不在 0~25% 时改用近五年均值，均值也不可用时按法定 25%，实际采用哪一档与退回原因写进 `warnings`（见 §5.2）。
- 首年残期不进 `warnings`：它是口径不是缺陷，所以由数字自己交代——面板的折现明细在那一行标「残期 0.50 年」，`/derivation` 的估值桥在营收合计与折现期两处写明窗口和截止日，CLI 的逐年明细给首年加 `*` 并在表下补一行说明。以前这里是每次估值都无条件附一句「stub 未单独处理」，2026-10-22 起那句随口径一起删掉了。

上面这些式子在 `/derivation` 的**链视图**里是带着数字摊开的：选定一行 → 「⤢ 放大这条链」弹出一张页内浮层，里面重画只属于这条链的小图（链尾 + 上游两层），下面逐行给符号式与代入式（§9）。那是显示层，不重算任何东西。

## 8. 归因、矩阵与自洽性校验

**单行归因**（`backend/model/attribution.py: attribute`）。对每个被改动的行：
```
退回只退这一行 → evaluate(current_inputs 里这一格换回 baseline) → per_share_reverted
贡献%   = (当前每股 − 仅回退此行的每股) ÷ 基线每股
改动%   = 当前值 ÷ 基线值 − 1
```
分母用**基线每股值**，所以「一次单独改动」的归因恰好等于面板显示的总变动，两列直接可比。级联行（`cost_of_equity`/`wacc`）不算人的改动（`changed=False`），否则会把自己重算出来的数当成人工修正，还会污染「改动行数」。

多行改动时归因列**不可相加**（单行敏感性天然非可加），面板的 `contribution_sum_pct` 存在但注明了这句话。`rate_if_reverted` 额外给出「只回退这一行时的折现率」，这就是「这行动了折现率」与「这行什么都没动」的区别。

**口径 × 终值矩阵**（`dcf.matrix`）：六个组合各算一遍每股值与折现率，缺条件的组合报出自己的拒绝理由（如 `FCFE/uem 需要正的 ROIC`），空白列本身就是信息。

**自洽性校验**（`dcf.cross_check`）：FCFF 与 FCFE 应该折**同一套经营现金流**，只有融资桥可以不同。所以检验的是流量而非每股值：
```
名义背离 = (ΣFCFF − ΣFCFE) ÷ ΣFCFF            超过 5% → 现金流定义问题（利息 / 净债务融资）
现值背离 = (PV_FCFF − PV_FCFE) ÷ PV_FCFF      超过 5% → 折现率问题（WACC 与 CoE 不再是同一资本结构）
```
`--rate` 把两条口径钉在同一个折现率上时，现值检验本身失效，会直接说明这一点。背离来自资本结构假设而非取数错误时，结论以 FCFF 为准。

名义背离那一支：`net_borrowing` 与租赁净融资是每年的 FCFE 流入，而 FCFF 里没有这一笔，所以两条口径的名义现金流天生就差这块；少数股东损益又只在 FCFE 一侧逐年扣掉。退出倍数与 UEM 两格的桥已经在终止年把累计净融资减回去了；Gordon 的终值分子也去掉了那笔净融资（§7 ⑥），剩下的只欠显性期那一截——每年的净融资进了 FCFE，利息又按逐年抬高的债务余额扣，再加上少数股东份额，这三块都是资本结构假设本身，不是取数错误。校验本身只跑 Gordon（`dcf.cross_check` 里两条口径都按 g 折），所以它报的是「现金流定义与折现率」这两件事，不是六格的平均值。

放大态是**页内模态浮层**。前两版都被实测否掉了：一版靠把无关部分淡到 0.15 来表达「不相关」，白底上一淡就等于擦掉，用户报回来的原话是「把无关链全部隐藏」；改成摊在整图下方之后，页面不滚就像按钮坏了。所以「干净」改由浮层里另画一张小图来保证——链以外的节点不是被变暗，而是压根没进这张图；背后整图一个节点都不动（点击普通节点时的淡出仍是 `.node.fade{opacity:.4}` / `.edge.fade{opacity:.3}`，那是选中态，不是放大态）。浮层打开时锁背景滚动（`body{overflow:hidden}`），否则滚轮会同时推走背后那张一屏多高的图。侧栏也跟着链尾重画，否则深链进来时它写着「未选中节点」而图上高亮着一组，两边对不上。

链视图的代入式同理不跑第二套算法：`derivation.SUBSTITUTIONS` 只声明「哪个符号是图上哪一行」（`{行 key}` 占位符），填数那一步在浏览器里用唯一的 `fmt()` 做（`common.js` 的 `substituteText`），所以式子里的数字与该行显示的值同源。只有**每个符号都在这行上游**的行才给模板（净债务、股权权重、股权成本、WACC、退出 EV/EBITDA、当前滚动市盈率六条形）；分子是序列端点或不落在 `derives` 里的量（LTM EBIT、净资产、末年营收、利息费用）就退回符号式 + 引用格清单——代进一个不相干的数，看上去是一条完整算式，实际把无依赖的行连成了依赖，而且只在放大页出现，图与面板都不会报错。少一行（老批次／无租赁口径）整条模板就不出。式子用的是显示值（比率两位小数），手算会与本行差在小数点后第二位，链视图那句话已经写在页面上。

## 10. 测试

无第三方框架，`tests/run_all.py` 自动发现 `test_*.py`（30 个套件），收尾再跑一次 DOM 哨兵 `tests/dom_derivation_check.js`（面板在跑就跑，没跑就打印「跳过」，不算失败）。几个哨兵值得知道，因为它们把「文档里的说法」变成可执行约束：

- `test_dividends.py`：分红这条通道自己的读法。三条读法各配一条反例（同年两笔必须求和且每 10 股÷10；分母只取年报行的每股收益——认错分母会把 75.1% 报成 106.5%，看着像特别分红而不像错数；`方案进度` 不含「实施」就落 `skipped` 而不是当零分红），`fetch` 在网络失败时仍然交回一个来源（对照：同样这一下发生在其余九个来源身上会把建链打死），且理由与空表统一成 `NO_RECORD` 那一句、原始报错只进 `fetch_error` 这个没人读的键（§12 第 19 条），落盘的是整张表而不是算好的比率，`dividends` 不在新鲜度的 expected 清单里（缺它照样判 `replay`）。最后一条是这个文件存在的理由：**级联侧 `test_terminal_growth.py` 用的是它自己造的 `payout_dict()` 桩**，桩与解析器之间本来没有约束，这里把顶层键、年度条目键、`special` 判据三处对齐（把 `sum` 改成 `max` 会红四条，实测过）。
- `test_derivation_graph.py`：凡有上游的行必须有公式、且只有它们有；没有一条边从右往左；**图载荷里不得出现 `per_share`/`equity_value`/`fcff`/`pv_`**（画图代码不许有第二套算法）；面板与图的「可编辑/级联/控件类型/金额行语义」四判据逐项一致。
- `test_assumptions.py` / `test_attribution.py`：`ENGINE_INPUTS` 的每个键都在生成的基线里存在，且「面板可编辑行」恰好等于那个 31 键集合（抓命名漂移与判据分叉）；营运资本的科目组成（合同负债、预付款项、应付职工薪酬必须计入，缺项时不按 0 补）。

- `test_recompute.py`：显性预测期这一行的三条语义——改年数现算年份集合（锚点一年都不许掉、上下限各钉一条、填得与基线同数就一字不改）、改宽之后人可以点名一个基线里从来没有过的年份（`{"horizon_target": 12, 增速行: {"2037": 0}}` 落得下，2036 那一年仍要拒）、老批次缺这一行时年数与增速行一字不变。外加三条归属哨兵：`horizon_years` 在 `DERIVE` 里但不在 `ENGINE_INPUTS` 里（它是计数，改了不动结果）；重导行只许三种身份——进引擎、只喂链上别的行、或像 `pe_ttm` 那样跟着上游重算的参考行；`pe_ttm` 就钉在第三种里（它不再进定价，但改市值与归母净利时这一格仍要跟着动）。

## 12. 已知限制

写在这里而不是藏在代码注释里：

1. **ERP 是 realized 历史超额，对窗口极敏感；默认档现在量得到数，但两把尺子没有并成一把**：级联取近 3 年那一档（`ERP_CASCADE_WINDOW`），今年／近 5 年／近 10 年只作对照。2026-10-14 那次以中证2000 全收益（`932000CNY010`）为市场腿，同一份快照四档实测 **+6.90%／−10.58%／+3.51%／−2.07%**——同一个指数、同一个 rf 序列，差着 17 个百分点，这就是链上留三行参考的全部理由（§4.4）。默认档落在 `ERP_RANGE` 内，所以那一批的顶层 `warnings` 是空的；旧的默认组合（000905 中证500 + 近 5 年）实测 −0.26%，「股权风险溢价退回惯例 6%」那时是每次建链都会亮的一条告示。**退惯例这套行为没有删**：换基准或换窗口后哪一档越界，级联就沿用惯例 `6.0%`、把被拒的实测值和原因写进行名与 note，并在顶层留警告；面板的窗口下拉也不会让人把负超额手动塞进 CAPM——`erp_window_options` 只把落在区间内的那几档标成可选，被拒的实测仍然摆在行上看得见。下界 0% 同时允许「低 β × 低溢价」把折现率压到永续增速附近，`THIN_SPREAD_WARNING = 3%` 与终值占比 75% 两道警告就是为此存在。**同一处还混着两把尺子**：ERP 那一格减的是同窗口国债中枢（3 年 1.97%），CAPM 前面的 rf 却是 `risk_free_norm`（5 年中枢 2.2943%），于是 CoE 比「ERP 也减 5 年中枢」的同尺算法高 β×(2.2943%−1.97%)——600519 这批 β=0.2324，差 7 个基点；β=1 的票上就是整整 32 个基点。它随 β 放大、不会随窗口消失，而不消掉它是因为 `--risk-free-basis` 的两个候选都锚在 `macro` 的固定 5 年窗口上，让 rf 跟着 ERP 窗口漂移会让那一行失去意义。
2. **全收益腿只在名单内那几只指数上存在，而且是税前口径**：分红在除权日再投资进点位、不扣红利税，所以它是总回报的**上界**；000001/399001/399006 与任何自定义代码都没有孪生（实测 `H00001` 回空表，深证成指与创业板指根本不由中证发布），退回「价格指数年化涨幅 + 乐咕沪深两市股息率」——那条路的分红腿是全市场 A 股而非指数成分，股息率还是当期收益率（不含再投资复利）。ERP 与 β 共用这条腿，所以名单外的基准上，β 回归用的也是价格指数，凭证里写明原因。四个孪生（`H00905`/`H00906`/`H00300`/`932000CNY010`）实测都能取满 11 年窗口，所以 `erp_10y` 对它们不特殊；序列起点早于窗口下限时截断的是请求区间，不是指数历史。**但「取满」不等于「都是真实行情」**：932000 与它的孪生由中证在 2023-08-11 发布，官网却把日线回到 2015-10-14，那 7.8 年是发布日之前的回算段（§12.10），取数层分辨不出。于是在默认基准上，`erp_5y` 的头 1.8 年、`erp_10y` 的头 7.8 年量的是指数公司补算的历史，只有近 3 年整段落在发布日之后——这是级联档定在近 3 年的第二条理由（§4.4）。
3. **首年残期是线性缩放，没有季节性**（2026-10-22 接入，式子见 §7 ⑤）：窗口按整月计（一季报后 9/12、中报后 6/12、三季报后 3/12），首年的营收、EBIT、D&A、CapEx、ΔNWC、FCFF/FCFE 一律乘上同一个比例，折现期同时缩短。三条要认的代价：① 乘同一个比例等于假设一年内的经营节奏是平的，零售与农业这类四季度占比高的公司，三季报后（s=0.25）的那一条线会被高估或低估一个季度级的量——免登录通道不给出分季度的现金流，季节性无从校准；② 非常规截止日（并购重组的期中截止，如 07-15）所在的那个月整月算作已走过，残期取 5/12 而不是 5.5/12；③ **这份改动换了折现轴，盘上以前量过的每一个每股差值都还是旧轴的数字**——§12.4 的 `revenue_ltm` ±10%、§6.1 的 5→10 年 +11.1%、§12.18 的正常化两臂、§12.1 的 β×rf 差 7 个基点，全部按同一比例整体偏移（新轴上 600519 这批是 +0.45%），比值与百分点差不受影响，绝对每股要重跑才与今天可比。跨批次比每股时这是第二个要问的口径差（第一个是年数，见 §12.17）。
4. **`revenue_ltm` 只经由三条 LTM 比率进定价，改它可以几乎看不见**：营收路径锚在 `revenue_base`（上一整年年报）＋一致预期增速上，LTM 营收不参与递推，它动的是 `ebit_margin_ltm`/`da_to_revenue_ltm`/`capex_to_revenue_ltm` 的分母（以及没有共识利润锚时的 `ebit_margin_start`）。实测 600519 批次 20261014-213556 营收 +10% → 每股 1,087.6769 → 1,087.6914（+0.0013%）：茅台首年 EBIT 率由共识锚定、纹丝不动，折旧与资本开支又各只占营收 1.3%，剩下的杠杆就这么多。**M2 之前的批次（行里没有 `raw`）分子无从重导，改 LTM 营收每股一字不变**（同一只票 20261013-233215：1,153.4923 → 1,153.4923）——所以那条「可编辑但不进定价」现在只对该老批次成立，新批次里它是活边。它自始至终在 `ENGINE_INPUTS` 的 31 键内，面板的「未定价改动」警报不会为它亮起（那个集合只收 `editable` 为假的行）。
5. **利息按逐年抬高的债务余额计提，不做还旧借新的再融资滚动**：显性期每年把 `net_borrowing + lease_financing` 加进债务基数（`利息_t = (有息负债 + 净融资 × (s + i)) × Kd_税前`，见 §7 ④），`net_borrowing` 按 LTM 水平重复。这笔净融资只在显性期流动：Gordon 的终值分子是「末年 FCFE − 当年净融资」，退出倍数与 UEM 两格的桥又在终止年把累计净融资从企业口径终值里减回去（§7 ⑥），三格里借款流量都不再被永久资本化。剩下的背离来自显性期的融资与利息，属资本结构假设本身，`cross_check` 的背离提示就是为此存在。
6. **EBIT 的科目口径**（§5.2）：`OPERATE_PROFIT + FE_INTEREST_EXPENSE − FAIRVALUE_CHANGE_INCOME`。三项各自的边界都写在这里——资本化利息不进 `FE_INTEREST_EXPENSE`（第 8 条），在建工程多的公司加回额偏低；投资收益与对联营合营企业的投资收益保留，因为长期股权投资没有从企业价值里单独扣过，对参股型、金控类公司这块利润仍留在 EBIT 里，与严格息前口径有偏离；资产/信用减值与其他收益保留在这一层的科目加回里不整块剔除，它们的偶发份额由 §5.2 `normalization_strip` 按官方扣非差额搬进分子（2026-10-22 接入，边界见第 18 条）。一致预期那一档是券商的营业利润，不做这两项调整。为了不让 `ebit_margin_path` 两端跨口径，锚点年自 2026-10-31 起在建链时整体平移 `机器 EBIT 率 LTM − 营业利润率 LTM`（§6.2）：平移只换水平，各年之间的相对变化保持券商原样，券商原值、同口径营业利润率与平移额都写进 `ebit_margin_consensus` 行的凭证与 `raw`。**平移量取决于公司**，同一 LTM 期两口径之差实测：600519 −0.03pp、300308 −0.02pp、300394 −0.69pp、300502 −0.63pp、000733 −1.55pp、002156 −6.75pp、603986 −9.65pp、300006 +1.52pp、002242 +1.56pp、002436 +2.32pp、603906 +4.82pp（各自最近一批的报表）。差得大的公司是利息费用或公允价值变动占营收高的那些（§5.2 的调整项）；平移只修正定义之差，不修正券商对未来的预测本身。2026-10-31 之前建的批次没有这一步，跨批次比 `ebit_margin_consensus` 时要记得。
7. **租赁只把非流动部分计为债务与融资**（一年内到期部分已在 `NONCURRENT_LIAB_1YEAR`，不重复计）；`lease_financing` 也按非流动差分。**已知边界（2026-10-31 决定保留现状）**：免登录的东财三表没有租赁负债的流动/非流动拆分，也没有「偿还租赁负债本金」字段，所以流动部分的变动既进不了融资项，也无法单独从 `NONCURRENT_LIAB_1YEAR` 里拆出来；`PAY_OTHER_FINANCE` 混着其他筹资支出（600519 最近一期 29.00 亿，远超其使用权资产摊销 0.26 亿），不能当作租赁本金。实测最近一批：600408 本行 −0.84 亿、使用权资产同比 −14.36%（反推减少约 0.69 亿）；603906 +0.36 亿对 +1.32 亿；600519 −0.26 亿对 −0.19 亿；600172 −0.56 亿对 −0.44 亿；300308 +0.87 亿对 +1.26 亿。没有改用「使用权资产余额变动」当代理：它等于新签租赁减摊销，分辨不出处置与减值，600408 与 600172 反推出的新签使用权资产为负（−0.54 亿、−0.03 亿）。FCFF 的资本开支只含购建长期资产、不含新签租赁取得的使用权资产，而 D&A 含使用权资产摊销，租约稳定时两者大致相抵，扩张时 FCFF 偏高、收缩时偏低，这条近似也一并保留。
8. **资本化利息既不进债务成本实测、也不进 EBIT 的利息加回**（`FE_INTEREST_EXPENSE` 只含费用化部分），在建工程重的公司这两项都偏低：债务成本被低估，EBIT 加回额也被低估。免登录通道拿不到资本化利息的披露额，这是数据边界，不是待办。
9. **β 依赖本批次价格快照**：前复权序列每次除权重排基准，隔天再取同一个 β 会变——所以价格原始答复必须落盘，`--from-run` 才谈得上复现。市场腿现在取 `market_returns` 凭证里的全收益孪生（与 ERP 同一条腿），孪生缺失或该基准没有孪生时才退回 `price_history` 里的价格指数；哪条腿写进行凭证，两份 `raw/` 都随批次落盘。
10. **中证官网的历史有回填段**：`stock_zh_index_hist_csindex` 会给指数发布日之前补上数据，起点那几段的样本质量与真实交易不同——默认基准 932000 就是现成一例：发布日 2023-08-11，官网实测仍回到 2015-10-14（价格指数与全收益孪生都是），前面 7.8 年全是回算，而这条通道交出的是**一条不分段的序列**，取数层无从标记哪一段是补算的（§12.2 因此把级联窗口钉在发布日之后）。它还会把请求的起始日原样回显成一条假收盘，解析里按「首行与次日同值」剔除（不剔除的话跨度护栏会被一条不存在的读数带偏）。
11. **换基准不再必然联网，但同一只票同时只跑一个作业**：请求的基准在这批的预取集合（§4.7）里时，面板给的是 `switch`——离线复现成另一个新批次，不碰网络；只有集合外（含 M4 之前只留一家凭证的老批次）才强制联网重取，因为旧快照的 β 与超额都属于另一个市场。**并入前先比整份 `BuildOptions`**（`backend/web/jobs.py` 的 `_inflight` 存的是 `(job_id, 那一次请求的参数)`）：参数相同（代码与基准都归一化之后相同）的第二次复用那个作业，这种复用是真省一次建链、产物同一件东西；参数不同则以 400 拒绝，回一句「`600519` 已有一个作业在跑：取数（基准 000906），当前「三表」；这次要的是 取数（基准 000300）……等它跑完再按」——同一只票同时只跑一个，参数不同的两个请求不并成一个。没有排队：排队会把两次完整联网串起来，而面板一次只能读一批。`force` 不进这份比较，因为强制重取在 api 那一步走的与「判旧了自动联网」是同一个 `BuildOptions`（都不带 `from_run`），正在跑的那个作业本来就在替它取新凭证。面板那两个按钮（取数估值／强制重取）在作业期间一起置灰、四处出口一起放开（`common.js` 的 `fetchValuation`）。这条改的是 2026-10-23 之前的一处谎：旧规则只看代码就并，于是「正在复现老批次时按下强制重取」会把那个零网络的 fork 当成刚取到的凭证答复（状态行写「取数用时 0.2 秒」），而换基准撞上旧作业时下拉会在几十秒后自己跳回前一个基准。哨兵：`test_panel_fetch.py` 的「同参数复用／换基准被拒且不留第二个作业且原作业照常在跑／复现作业不回答取数请求」，`test_routes.py` 的「两个按钮一起置灰、没有只放开取数按钮的出口、四个出口一起放开」。
12. **退市／查无此票的代码在联网之前就被名录拦下（2026-10-15，见 §4.1 末段）**：旧行为是把十个来源加 M4 那十一条指数序列全跑完、最后一步才炸；现在 `builder.admission()` 在 `RunStore.create` 之前否决，CLI 以 3 退出，面板新鲜度那一行写「✗ 查无此票」、按下不排队，被拦时 `runs/` 下一个新目录都不留（实测 600001：0 秒、零网络请求，`runs/600001/` 仍是 2026-09-24 那两个旧批次）。**这道闸门买的是成本与文案，不是正确性**：实测新浪的日线接口对退市代码直接回空表，旧链路的终点本来也是 `PricesUnavailable`——数字不会错，只是白跑一遍，还把「稍后重新取数」这种建议摆在对一只退市票身上。名录答不了的两条一律放行（盘上没有索引、索引旧过七天），所以刚上市的票会被拦在门外，出路只有 `python scripts/update_universe.py --force`（约 30~60 秒）：**没有** `--allow-unlisted` 这类后门，这是当天定的口径——名录就是最终裁判，「强制重取」只管新鲜度、不管准入；复现路径根本不查名录（盘上的历史批次今天否决不了）。北交所与 B 股那一半挪到了构造期：`Ticker` 不再把 920xxx/900xxx 当沪市、200xxx 当深市，而是在拼出可发请求的 secucode 之前就报「板块未接通」（搜索页照列、标灰）。**仍然管不到停牌**：名录里没有交易状态这一列，「今天停不停牌」它答不了，停牌票照旧走完整条链，行情那条腿取到的是最后成交日之前的序列。
13. **行情降级只到「现价/股本」级别**：push2 挂了就退腾讯，两者都挂时 `price`、`market_cap`、`equity_weight` 一串都空，级联回退到基线存量 WACC 并在 warnings 里说明。

15. **再投资增速档只在「稳定分红＋有官方 ROE」的公司上成立，而且它不是定价输入**：三个缺口都是结构性的——① 2026-10-16 之前的批次没有 `raw/dividends.json`，这一行永远空白（不重跑取数，也不假装是 0）；② 分红明细里「实施」之前的行一律不算，预披露被取消的预案因此不会污染窗口，但**已宣告未除权**的那笔也一并被排除在当年之外，年末几个月里最近一年的分红率会偏低；③ `ROEJQ` 是加权口径，与报表净资产反算的期初期末均值不等价，两个数本来就常差一两个点，这里直接采官方那一列（§4.1）。所以这一档的角色是**对照**：它摆出「利润留在公司能撑起多快增长」，与级联那一档之间的差就是市场对「超额收益能持续多久」的定价差；把它当成永续增速填进级联行，几乎必然让 `g ≥ r`、Gordon 与 UEM 同时无解（引擎会拒绝出数，这是设计而非 bug）。**盘上带这一档真数据的批次仍然很少**（2026-10-25 逐批实测）：`runs/` 下 17 只票有批次，这一格算得出数的只有 5 只——600519 +14.38%、301190 +2.75%、600036 +10.54%、601899 +17.76%、600408 +11.75%；688561 有分红凭证但源上查不到分配记录（该行判不可用），000651 最新一批没有分红凭证（那份表只在 10-22 建链失败的残批 `raw/` 里），其余 10 只票（000001、000002、000776、000858、001339、600001、600002、600028、601318、603938）一次都没碰过这个来源，其中 600001/600002 是 §12.12 那两只查无此票的准入证据批。跨批次比这一格之前先看清源批次晚于 D1 没有。手工复算与逐笔配对的对照写在 §5.2 该小节。
16. **多基准预取的线程池偶发 V8 abort（已修，2026-10-23）**：原先的症状是 CLI 建链时 `IndexSeriesMap.load()` 的 worker 里偶发 `[FATAL:partition_address_space.cc(243)] Check failed: !IsConfigurablePoolInitialized()`，进程当场死掉、**没有 Python traceback**，批次只落到 `raw/`（没有 manifest/baseline），同一份代码重试即通过（2026-10-16 连测：炸、炸、通过；2026-10-23 修前 30 轮重跑：第 24、30 轮炸，退出码 2147483651，即 `0x80000003`）。原生栈 `python313 → _ctypes → ffi → mini_racer.dll → _make_context`，指到 akshare `stock_zh_index_daily` 每次调用都新造的 `py_mini_racer.MiniRacer()`。
    - **抢的是「第一次」，不是「主线程」**。旧注释与 §4.7 从前都写着「V8 在非主线程初始化会炸」，所以只把 `import akshare` 挪到主线程——那条预热根本挡不住：import 不构造上下文，而现场崩溃的那一轮 `_akshare()` 早已在主线程跑过。真正的判据是**进程级第一次初始化不容许两条线程同时来做**。修法就是开工前单独建一个引擎上下文再丢掉（`prices._warm_v8()`，带模块级锁与 once 标志，免得两个调用方同时预热反倒复现这条坑）。
    - **证据分两层**。① 不联网的机制实验 `python scripts/probe_prefetch_warmup.py --parent --warm <0|1|2>`（只重复 `MiniRacer()` 构造，8 线程 × 40 轮，每个进程一个干净解释器）：不预热 46 个进程死 13 个，先建一次 46 个死 0 个（其中主线程先建 26 个、后台线程先建 20 个各 0 死），单侧 Fisher `p≈5×10⁻⁵`；「后台线程先建也安全」（`--warm 2`）这一条正是面板那条路的许可证——`builder.build()` 跑在作业线程里，如果坑真名叫「非主线程」，这个修法覆盖不到它。② 联网端到端重跑 `python scripts/repro_prefetch_abort.py --rounds 30` 两批共 60 轮：0 轮被崩溃打死，且 60 轮都自查护栏确实生效（跑通了但护栏没生效一律记失败，否则一批没炸可能只是没踩到）。若崩溃率仍是修前量测的 2/30，纯运气跑出 0/60 的概率是 1.6%。**两层的分工是刻意的**：端到端计数只证明「没再犯」，证明不了「修对了」；机制实验才回答因果，而且它不烧配额。
    - **`--rounds` 那台重跑机器留在仓库**（每轮一个新进程，因为原生崩溃只与进程里第一次初始化有关，同进程内循环复现不出来；`--build <代码>` 换成整条建链看它停在哪一步，`prices.fetch_frame` 包了一层打印哪个线程在调哪个函数）。它自己也被修过两处判读：一是退出码 `0x80000003` 以前不标注，现场那两次崩溃在日志里只剩一个光秃秃的数字；二是自查的判据从前写成「预热要排在**所有**取数之前」，`--build` 一跑就报假违规——整条建链里 `macro` 的股息率腿（`stock_a_gxl_lg`）本来就排在预取之前，那是主线程上串行的一次构造，正是安全形态。判据收窄成这条坑真正的名字：**线程池的 worker 不许抢在第一次预热之前取数**（`racing-fetch@ThreadPoolExecutor-*`）。护栏没生效也不再与崩溃混数，它单独一个退出码 97，汇总里分开点：一次配置错误被数成一次崩溃，会让「修法有没有效」这个问题得到错的答案。
    - **当天的一点环境噪声要说清**：这 60 轮里有 39 轮只到手 6/11 条序列——中证官网那条通道当时整段回非 JSON（独立探针重试 4 次仍 `JSONDecodeError`），另 21 轮到手 7~11 条（其中满载 11/11 的有 18 轮）。这不影响这条坑的判定：炸的那条腿是新浪的 `stock_zh_index_daily`（只有它建 JS 上下文，官网那条是纯 HTTP），新浪那几条在每轮都照旧并发跑；机制实验本身根本不碰网络。官网通道什么时候恢复另说，它属于 §4.7「失败隔离」那一条管的事实——缺的那几个基准不进预取集合，切到它们照常判「需联网」。当天晚些时候用修好的重跑机器复跑（1 轮 `--build 600519` + 3 轮纯预取）就是另一番景象：官网那条四条腿全回，预取 11/11 满载，两种形态都 0 崩溃、护栏都报生效。

24. **FCFE 从合并税后净利里逐年扣少数股东损益（2026-10-31 接入，式子见 §6.3 与 §7 ④）**：从前 FCFE 拿 `(EBIT − 利息) × (1 − 税率)` 当税后净利，这是合并口径——少数股东分走的那一份也在里面，折出来的股权价值于是把子公司的少数股权也卖给了母公司股东，与 FCFF 侧减 `minority_interest` 的处理不对称。现在新增第 55 行 `minority_profit_ltm`（LTM 少数股东损益），按 LTM 占营收比逐年扣掉；Gordon 的永续分子取末年 FCFE，这一扣已经含在里面。只动 FCFE 三格：FCFF 三格逐字不变（它的现金流本来就是全投资人的），UEM 与退出倍数两格的终值是 NOPAT / EBITDA 企业口径，本来不含少数股东份额，桥在终止年减的是少数股东权益余额，不重复扣。这一行进 `ENGINE_INPUTS`（30 → 31 键）；缺失时只在 FCFE 下报警并按 0 计，FCFF 不报警——老批次没有这一行就是这个形状。

25. **营运资本补进合同负债、预付款项与应付职工薪酬（2026-10-31 接入，式子见 §5.3）**：从前 NWC 只算「应收票据及应收账款 + 存货 − 应付票据及应付账款 − 应交税费」。合同负债是客户先付的钱，随营收增长本身就是经营融资，漏掉会把资金占用算大、把 FCFF 算小；预付款项与应付职工薪酬同理。现在按组取第一个非空键，加上预付款项，减去合同负债与应付职工薪酬。其他应付款、其他应收款、合同资产没有加：东财 `GBALANCE` 在盘上 60 个批次的这三个键全为空值，是数据缺口，不是口径选择。合同负债自 2020 年新收入准则起才有，更早年份叫预收款项，本口径没有映射；盘上批次的近五年窗口是 2022 年以后，不受影响。
